八、诚实说明
  · **「未命中」不等于「确认正确」**：判定全是查表（工具名在不在注册表、
    参数与 schema 一致否），未命中只说明这条轨迹通过了我能查的那几项。
    以 xlam 为例我**拿不到执行反馈**，所以「正样本」的准确含义是
    「没查出缺陷」，不是「业务结果正确」。
  · 这批是**已清洗过的公开数据集**，命中率只有 2.25%，
    并不代表生产环境的比例——真实 Agent 轨迹会更脏。
  · 「工具不存在」这一项 0 命中：样本里的调用都落在给定工具列表内，
    因此**这一项没被验证到**，不能说它能查幻觉工具名。
  · 该数据集**没有 `required` 字段**：本批扫过的 168870 份工具定义里，带 `required` 的是 0 份——所以
    「缺参数 = 漏填必填项」这个前提**不是数据源声明的，是我自己设的口径**。
    据此判出的 1286 条因此从「丢弃」改判为「工具 schema
    缺陷」：模型省略一个描述里写着有默认值的参数，是合理行为，不是错。
  · 查不到的脏（如参数值语义错误）照查不出——这是查表法的天花板。
  · 「default 错位」是**事实 + 一次推断**：值确实落在别的参数上
    （事实，可在 schema 里逐字复核）；「作者本意是给 description 声明的那个
    参数」是推断。逐项看，`calculate_electric_field` 那一项推断很硬——
    8.854e-12 是真空介电常数，不可能是 int 型 charge/distance 的默认值；
    `mean_confidence_interval` 那一项的推断弱得多（0.95 作标准差并非
    不可能）。报告不替读者决定，把两种强度都摆出来。
  · 我试过一个**更硬**的探针查「类型与默认值是否自相矛盾」——不依赖任何
    description 措辞，纯机械规则。全量跑出 2162 个命中，我看了一眼就判定
    它是假的：本批 260944 个带 default 的参数位里，有 232552 个
    （89.1%）的 default 是**字符串**——
    `type: int` + `default: "10"` 是这个数据源的表示层约定，不是矛盾。
    **探针已删除，没进报告**：留一个抓错东西的探针，不如少一个探针。
    （这个 2162 随之不可复现，只作为一次自我否定的记录留着。）
  · 已知未解决：重复调用探针（`probe_retry_storm`）判「同名且同参数」
    重复，但幂等性是工具属性、我拿不到——`draw_cards` / `get_random_question`
    这类工具，用同样的参数再调一次是**正常动作**。该探针在本批 0 命中，
    即**未被真实数据验证过**，所以按拆表法先不动它，留作开放问题。
