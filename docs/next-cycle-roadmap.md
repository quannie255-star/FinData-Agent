  有失败证据的工程闭环，优先于规模扩张；
- 附属功能三判据（parking-lot 2026-10-10 条）：与主线复用 ≥ 80% 或直接补
  主线短板；成果能写回主线叙事（"因此把 X 指标从 A 做到 B"）；有外部锚点
  （AFAC2027 报名窗口预计 2027-05~06，恰在锁期满之后）；
- 铁律全部沿用（AGENTS.md）：评测先行、声明与代码一致、成本如实、
  数字必须对应 examples/ 可复现归档。

## 2. 阶段 0：锁期内即可做（主线内质量与叙事，不改方向）

### 2.1 L1 表格保真检索（第一期）

- **做什么**：`convert_pdf` / 文档入库路径保留表格结构——用 PyMuPDF 的
  表格检测把表格区还原为 Markdown 管道表（当前被剥成散文，表头标签丢失，
  是 recall 8.1% 的已定位主因）；检索层让表头/标签进独立字段参与 BM25F
  加权（字段权重纪律已有）。
- **验收门禁（先行写入）**：FinanceBench recall@8 从 8.1% 复测，
  目标 ≥ 25%（目标值在第一次复测后诚实修订）；中文回放 golden 9/9 不回归；
  转换前后字符台账归档 examples/。
- **为什么不违反方向锁**：外部权威基准校准是 afac-track4 既定工作线
  （2026-10-08 起步），L1 是其失败模式的修复，不是新域。

### 2.2 C1 输出合规层（免责 + 角色边界）

- **做什么**：①前端与答案层固定免责声明（"信息整理与文档检索，不构成
  投资建议/法律意见"）；②对"该不该买/值不值得投"类**决策建议型问题**，
  系统拒答并转引客观事实口径（角色定位写进 system prompt + 代码层拦截）。
- **验收门禁**：评测集新增 ≥ 8 道决策建议型问题（五域各 ≥ 1），断言
  拒答 + 转引行为；测试进 CI。

### 2.3 C3 引用覆盖率审计（把归因讲成合规能力）

- **做什么**：现有 M4 归因校验"引用是否真实在场"；再加**反向度量**——
  答案中的关键数字/断言被引用覆盖的比例。覆盖率 < 100% 时如实标注
  "以下内容未直接引用原文：…"。
- **为什么**：金融监管的核心要求是"结论可追溯依据"。这把项目已有的归因
  资产翻译成合规叙事，是面试里"合规即产品能力"的差异化故事。
- **验收门禁**：覆盖率进 token 台账同一张表；至少 3 次真实问答归档对比
  （覆盖率 100% vs 不足时的标注形态）。

### 2.4 既有待办顺延（afac-track4 §7 不变）

- fin_s_004 单题 43K token 的复审链上限；求职材料收尾；留意同类比赛与
  实习机会。

## 3. 阶段 1：锁期满（2027-01-04）→ 2027-03

### 3.1 L2 英文查询与字段适配

表头别名扩展（revenue / total revenue / net sales）、英文表格标签的
BM25F 字段权重调优、查询改写一期。**验收**：FinanceBench answer@8
从 33.3% → ≥ 50%；recall@8 保持或高于 L1 复测值。

**进展（2026-10-10）**：词法侧一期已随 §8 首批落地（recall@8 16.16%、
answer@8 37.37%），门禁未达——剩余瓶颈是纯词法失配（题问与 10-K 行文
词汇不同）。**L2 深化 = 混合检索立项**（见 §3.1.1）。

### 3.1.1 L2 深化：混合检索（BM25 + 向量，新基础设施，2026-10-10 立项）

- **裁决（§5 决策点 1，2026-10-10 所有者指令）**：产品口径启用 embedding，
  混合检索作为独立立项做消融。赛题纪律（禁 embedding）仅约束赛题口径
  ——评测线（isolate/baseline/提交物）保持纯 BM25F 不 import 向量模块，
  对外引用赛题纪律时必须注明产品形态的差异。
- **做什么**：`finqa/embedding.py`（嵌入后端协议 + 本机 ONNX 推理
  （fastembed，extra=embed）+ 百炼 API 兜底 + 内容寻址缓存）+
  `finqa/hybrid.py`（RRF 名次融合，无调参、确定性，k=60 TREC 标准）；
  评测脚本加 `--retriever bm25|hybrid|vector` 三臂消融。
- **验收门禁（先写后做）**：FinanceBench 99 题 answer@8 ≥ 50%
  （基线 37.37%）；recall@8 ≥ 16.16%（不回归）；bm25 臂复测与 v2 归档
  逐位一致（确定性验证）；中文路径零改动（BM25Index 不动，测试全绿）。
  目标若未达：如实记录并按 L1 惯例诚实修订，不带病调参。
- **诚实边界（随归档输出）**：向量模型输入截断至 512 token（bge 系上限），
  向量臂只见块前部、BM25F 仍覆盖全文；本机推理模型指纹与缓存位置写进
  报告；百炼 API 后端（若用）的 embedding token 用量如实记账。
- **进展（2026-10-10 补跑，三臂归档 `examples/financebench-recall-v3/`）**：
  bm25 / vector / hybrid 三臂全部跑完（99 题）。**结论：真正的杠杆是向量臂
  本身，不是等权融合。** recall@8 纯 BM25F 16.16% → 纯向量 **41.41%**
  （recall@16 25.25% → 55.56%）；**等权 RRF 混合反而弱于纯向量**
  （recall@8 21.21%、recall@4 14.14%）——两臂强弱悬殊时等权融合把一半名次位
  让给劣质臂；answer@8 三臂同为 37.37%（k=8 上下文已大到答案数字常在里面）。
  **门禁未达**（answer@8 ≥ 50%）：如实记录，不带病调参——下一杠杆改为
  「加权融合 / 向量召回 + BM25 重排」两阶段。确定性：bm25 臂与 v2 归档逐位
  一致；hybrid 臂 `embed_calls = 0`（内容寻址缓存命中）。详表见该目录 README。

### 3.2 L3 多语言口径声明（诚实边界）

英文问题原题作考卷、答题语言跟随问题语言；**其余语言明确不做**（语料与
预算不支持，声明写进产品"擅长/不擅长"页）。跨语言检索（中文问×英文文档）
只做可行性探针，不成工作流。

### 3.3 D1 扫描件 OCR 兜底（赛题二附属启动·最小可用）

- **做什么**：图片型 PDF → 本地 OCR（候选 RapidOCR / PaddleOCR，Windows
  CPU 可跑、许可证允许商用讲述）→ 注入现有 `convert_file` 管线。只做
  "扫描件从不可用到可用"，不做版面理解。
- **验收**：一份扫描版 PDF 端到端可问答；OCR 失败给出明确报错而非静默
  空文本；转换质量抽检归档。

### 3.4 C2 数据合规完善

PII 脱敏上传选项（开关默认关、明示风险）；数据驻留说明（提问片段发往
阿里云百炼的 region 与用途）；**公开部署前置清单**（鉴权 / 限流 / 审计日志
——只列清单不实现，公开部署本身超出求职目的即不做）。

### 3.5 真实用户观察

个人版外部真实使用者 ≥ 3 人，反馈进 docs/ 复盘。求职叙事从"能演示"
升级为"有陌生人用过"。

## 4. 阶段 2：2027-04 → AFAC2027 报名窗口（D 系列闭环 + 参赛决策）

### 4.1 D2 版面分析 + 表格结构化完整闭环

同一批文档"还原前 vs 还原后"的检索召回对比（中文扫描件 + 英文 10-K

### 4.3 参赛决策点（2027-05 前裁决）

## 5. 显式决策点（诚实清单，需所有者裁决，不默认）

1. **embedding 解禁**：题面禁 embedding 是比赛口径。若 L2 后英文 recall
   仍卡住，混合检索（BM25 + 向量）是明牌解法——仅限**产品模式**启用并
   显式标注"违反赛题纪律"，是否开由所有者裁决；
   **✅ 已裁决（2026-10-10 所有者指令）：产品口径允许 embedding，混合检索
   按 §3.1.1 立项做消融；赛题口径评测线不动（不 import 向量模块）**；
2. 模型升级（qwen3.7-plus 与题面基准的口径差）影响成本与可复现性对照；
3. 公开部署（超出本机演示）：触发 C2 前置清单，否则不做。

## 6. 停止清单

- 不加第五个评测域、不做中文英文之外的第三种语言；
- 不做实时行情接入问答（与赛题一"交易行为识别"划清界限——那是独立立项
  级别的方向，不属附属）;
- 不做法规更新订阅 / 时效追踪服务（C 系列只做文档日期元数据的轻量时效
  标注）；
- 附属功能同时最多一个；任何新方向先进 parking-lot。
