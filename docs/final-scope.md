# 终局范围与收敛判据

> **本文管"收敛到哪、什么算做完"**；`product-goals.md` 管"逐条目标与差距"（其 §3 的 P0 清单按本文重排）；
> `interview-story.md` 管"会被怎么检验"。
> 本文所有"现状"只许写四种值：**已达成 / 部分 / 未开始 / 无法核对**。写不出判据的目标不算目标。

## 0. 决定（2026-09-27）

**收敛到金融数据可信方向，暂停换域与升级规划。** 冻结的是"换域与加新能力"，不是停手。

依据**不是**"它是最初的方向"（那是怀旧，不是理由），是三条可核对的事实：

| 事实 | 证据 |
| --- | --- |
| ① 唯一有**运行证据** | `logs/daily/` **17 次启动 / 16 次到达巡检**（10 个日志文件，自 2026-09-15 起）；游程编码 `(告警 7/抑制 0/健康分 72) × 5 → (1/8/96) × 11`（见 `examples/daily-pipeline-run-history.md`） |
| ② 唯一有**真门禁** | `test.yml` 的 e2e smoke **真起 uvicorn** 再 curl 四个路由断言；eval-gate 钉 golden `--strict` + 召回/精确/抑制 **≥0.9** |
| ③ 收敛**成本最低** | `pyproject.description` 本来就是金融侧（四档徽章 + 通用包 + A 股领域包）⇒ 只需改 `version` |

对比另两个域：更换域的 v4.0 是实验台 —— 外部用户 0、云端模型从未跑过、任务是自撰 32 道。
**它的价值是方法学，不是产品。**

## 1. 这个项目最终的目的是什么

> **把「这个数字能不能用」从口头判断，变成一份带证据链、可被第三方核查的产物。**

一句话拆开：

- 它**不生产数字**，它回答「这个数字可不可信、为什么」。所以它的差异化在**归因**，不在检测
  —— 缺 6 行是漏采还是停牌，需要领域知识（交易日历、公司事件、截面共动性）才能判。
- 判断的形态是**处置**，不是打分：`✓ 正样本 / ⚠️ 需人工 / ✗ 丢弃 / ⊘ 不算失败 / 待修 schema`。
  其中「待修 schema」是根因在数据源时，**处置作用回数据源**。
- 它已被验证能换域两次（agent 轨迹、上下文预算）。这是**「这套判断不是只会一件事」的证据**，
  **不是两个额外产品**。

⚠️ 必须同时挂上反面：**三个域都做成半成品 = 三个都不是产品。** 这正是要做这次收敛的原因。

## 2. 五个目标词的判据

### 2.1 跑过真实数据 —— **已达成，且是全项目最强项。要保护它。**

| 判据 | 现状 | 证据 |
| --- | --- | --- |
| 数据来自真实外部源，不是自造 | 已达成 | akshare；25 标的；28,652 行行情；知识层 `corporate_event` 1,165 行 |
| 有连续运行记录（不是"我跑过一次"） | 已达成 | **17 次启动 / 16 次到达巡检**（10 个日志文件，自 2026-09-15 起），多次固定 18:30（计划任务） |
| 有前后对照（修好了什么） | 已达成 | 游程编码 `(告警 7/抑制 0/健康分 72) × 5 → (1/8/96) × 11`，见 `examples/daily-pipeline-run-history.md` |

**差距**：数据源只有 1 个；25 只是自用规模。
**纪律**：这条是重构中最容易被弄丢的东西 —— 重构时宁可慢，不要让"连续运行 + 前后对照"断掉。

### 2.2 工程成熟 —— **部分。判据是"陌生人能不能跑起来"。**

| 判据 | 现状 | 差距 |
| --- | --- | --- |
| 有 `LICENSE` | **未开始** | **仓库是公开的、`license: None`** ⇒ 法律上默认保留所有权利，别人看到也不能合法复用。这是"不是 toy"的**硬门槛**，且成本最低 |
| 一条命令跑通离线 demo | 部分 | `findata-trust-report` 已存在，但没有"5 分钟、离线、无浏览"的示例 |
| CI 门禁真的在拦 | 部分 | **见下方修正** |
| 版本号/描述与代码一致 | 部分 | 描述已对；`version` 仍 `2.2.0` |
| 别人 clone 下来能跑 | **未开始** | 每日管线的调度任务**不在仓库里注册**（Windows 计划任务），仓库里只有它留下的日志 |
| 依赖锁定 | 已达成 | `uv.lock` |

**一处必须修正的旧说法**：此前记的是"主赛道在 CI 里 0 门禁"，说得太绝对。核实后是：

- `test.yml` **拦得不少**：`ruff check src tests`、全量 `pytest`、**e2e 真起服务 + 路由断言**、
  golden `--strict`、质量下限 `recall/precision/suppression ≥ 0.9`。
- 但准确的问题有三条：① **没有一条门禁是为主赛道写的**；② **`scripts/`（8,663 行，主赛道的交付载体）不在 lint 范围**（`ruff check src tests`）；
  ③ **`ci.yml`（那条 `ruff check .`）只在 `main` 与 PR 上触发**，而主开发直推 `master` ⇒ 它平时不跑。

### 2.3 高可用 —— **部分。但先给"高可用"下对定义。**

对"每天跑一次的管线 + 一个 CLI"，高可用**不是** 99.99% SLA，是这四件事：

| 判据 | 现状 | 差距 |
| --- | --- | --- |
| ① **不会挂死** | **未开始** | `scripts/daily_pipeline.py` 调子进程**没有 timeout** ⇒ 采集挂住则整条管线永久挂住（LLM 侧有 60s 超时，子进程侧没有） |
| ② **不会毁用户状态** | 部分 | 写产物非原子（直接 `write_text`）；重跑是否幂等需逐条核 |
| ③ **坏了能诊断** | **已达成** | 日志 + 退出码；`schtasks.log` 里 09-15 那次崩溃的完整 traceback 就是证据 |
| ④ **部分失败如实报** | 部分 | 目前基本是"全成功或崩"，还没有"部分成功、并说清哪部分失败"的形态 |

### 2.4 有业务思维 —— **最弱的一条，而且不能靠写文档补。**

| 判据 | 现状 | 差距 |
| --- | --- | --- |
| 能一句说清"谁在什么场景用它" | 部分 | `business-case.md` 有论证，但**使用者是自己** |
| 成本如实（token/时间进报告） | 部分 | 日报有字符入/出与耗时 |
| 有取舍记录、有不做清单 | 部分 | `product-goals.md` §5 有"明确不做"八条 |
| **有外部真实使用** | **未开始** | 外部用户 **0** |

⇒ 这一条只能靠一件事补：**至少一个不是你的人，在你的产物上做过一次决定。**
在这一条之前，"有业务思维"只是自我评价。

### 2.5 不是 toy —— **只有一个判据：有别人跑过。**

- 这条**无法由自己声明**，也无法由代码量、测试数、star 数代替（`stars: 0`）。
- 最便宜的达成路径：① 补 `LICENSE` → ② 离线 5 分钟示例 → ③ 让一个陌生人**用他自己的数据**
  跑一次 `findata-trust-report`，把结果发回来。
- 在拿到③之前，任何"不是 toy"的表述都是过头的。

## 3. 冻结清单（"做精"的代价，必须写死）

**冻结（不做）**

- 不换域、不开 v5.0 命名、不加新子包
- 不加新探针类型、不加新归因类别（**加类别会让质量下限的 0.9 失去意义**）
- 不再改首页叙事方向（README/PITCH 已在 09-23 定型一次，再改就是第三次横跳）

**允许（继续做）**

- 修 bug、补测试、补文档、补归档
- 把**已有**能力接到真实使用场景
- §2.2/§2.3 的工程项（许可、超时、原子写、lint 覆盖、版本号）

**判据一句话**：**一个改动如果不增加"别人能跑起来"的概率，就先不做。**

## 4. 未决（需要本人拍板，不擅自决定）

1. **数据源要不要扩到 2 个以上。** 单一源是"玩具感"的主要来源；但扩源要改采集层，属于第 3 节的边界地带。
2. **标的数 25 → 多少。** 这个数取决于"给谁用"，现在还不知道。
3. **要不要把每日管线做成"别人也能注册的任务"**（跨过 clone-跑不起来 那道门槛）。
4. **公开仓库要不要继续公开。** 现在是公开 + 无许可 ⇒ 要么补 `LICENSE`（推荐 MIT/ Apache-2.0），
   要么改私有。**两条路都比现状好。**
