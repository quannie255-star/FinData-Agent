## 0. 赛题事实（来源：官方完整题面，2026-10-04 取得）

**赛题**：AFAC2026 挑战组赛题四「金融长文本 Agent 的动态记忆压缩与高效问答

### 0.1 任务与硬约束（架构级，先记这两条）

1. **推理问答阶段只许 Qwen**：不得修改基座参数，仅通过**阿里云百炼或魔搭**
   调用 Qwen 系列 API（题面注明基准模型 Qwen3.6-plus，见 §0.5 不一致 #3）。
   **禁止任何 embedding 模型参与检索与推理**；非 Qwen 模型的向量/排序/召回/
   rerank/投票/纠错/语义摘要一律不得进入正式答题。
2. **预处理白名单**：PDF 解析、版面分析、表格恢复、阅读顺序还原等**结构化
   处理**允许用非 Qwen 工具（题面点名 MinerU 属允许范围）——但只限"解析与
   结构化"，语义结论必须出自 Qwen。

⇒ **检索层的合法形态**：关键词/术语/条款编号/结构化字段索引（题面推荐
「面向金融术语、条款编号和指标名称的混合检索」，即 BM25/规则类）+ Qwen
做候选判断。这与本仓库「归因用查表不用 RAG」的既有论证同构——不是妥协，
是赛题把我们的默认路线写进了规则。

### 0.3 评测公式（策略含义见 §4.0）

```
Accuracy    = Correct / Total（多选题无部分分：漏选/错选/多选均判错）
TokenBudget = 5,000,000
TokenScore  = max(0, min(1, (TokenBudget − TotalTokens) / TokenBudget))
FinalScore  = 100 × Accuracy × (0.7 + 0.3 × TokenScore)
```

- Token 统计覆盖**全过程所有 API 调用**（检索摘要、压缩、证据判断、答案
  生成、自检），不藏得住也不许漏报；
- 同分裁决顺序：准确率 > 低 token > 早提交。

## 3. 差距（要新建的，按依赖顺序；约束已按 §0.1 修正）

1. **Qwen API harness**：百炼/魔搭接入，统一解码参数、token 计量落账
   （题面要求全过程 token 可汇总，`成本如实`铁律的落地形态）；
2. **评测器**：按 §0.3 公式实现打分（Accuracy + TokenScore），输出对照
   官方 baseline（A 49% / B 13%）的分项报告；评测集固化为 golden 进 CI；
3. **文档预处理管线**：PDF → 结构化文本（MinerU 类，白名单内），保留
   标题/章节/条款编号/表格——条款编号是检索锚点，不能在解析时丢；
4. **检索层**：关键词/术语/条款编号/结构化字段索引（BM25 类）+ Qwen 候选
   判断；B 榜模式不给 doc_ids，检索即最大失分点（baseline 13%）；
5. **跨轮记忆流转模块**（真正的新东西）：多轮读取-压缩-推理过程中的事实
   保留与冗余淘汰，v4.0 只做过单轮上下文预算。

### 3.5 技术选型：轮子优先（2026-10-05 定，作者指令）

**有成熟轮子的不造，能用成熟框架就用**。自研只发生在没有轮子的地方——
而那恰好是差异化所在（判据与验证），基建自研是这个项目过去最大的浪费来源。

| 层 | 用什么 | 不做什么 |
| --- | --- | --- |
| PDF 解析 | **PyMuPDF**（确定性提取，M1 已用）；版面复杂时上 **MinerU**（题面白名单） | 不自写版面分析/表格恢复 |
| 检索（M2） | **rank-bm25** 或 LlamaIndex `BM25Retriever` | 不手写 BM25/打分器（embedding 仍禁用，§0.1） |
| Agent 编排 | **LangGraph**（仓库既有依赖与文化：有回环才用图） | 不自写循环状态机 |
| 记忆/压缩朴素臂（M3） | LangChain / LlamaIndex 现成 memory / compressor 组件 | 朴素臂就该是"标准做法"，自研只做证据驱动的改进层 |
| 数据校验 | **pydantic**（题集加载已用 `model_validator`） | 不手写校验链 |
| 模型接口 | **openai SDK** 打百炼 compatible-mode | 不裸写 HTTP |
| **自研边界** | 评分口径（§0.3）、token 台账、引用观测归因（M4）、配对验证（M5） | ——这些没有轮子，是项目立身之本，**不许**用框架糊掉 |

（pymupdf 目前为 ad-hoc 安装，正式成为依赖待预处理管线立项时一并入
`pyproject`。）

## 4. 里程碑（评测先行：先把评测接成门禁，再写策略）

### 4.0 评测公式的策略含义（先算账再动手）

- 系数区间 [0.7, 1.0]：**准确率主导**。准确率每 +1% ≈ +0.7~1.0 分；
- token 从 6.87M（baseline）压到 5M 是第一道坎（TS 0→0.375 之间）；
  压到 2.5M 得 TS=0.5（Acc=80% 时约 +12 分）；边际收益随压缩递减，
  **准确率掉 1% 需要约 833K token 的节省才打得平**（在 Acc≈80% 区间）——
  压缩永不许伤准确率，这与「删信息不可逆」判据一致；
- B 榜（盲检）是决胜局：A 榜 49% 说明读得对，B 榜 13% 说明找不到。
  **检索优先于压缩**。

### 4.1 M1 读数与发现（2026-10-05，examples/afac-scaffold-baseline-m1*.txt）

- **qwen-plus**：4/5，总 token 8,210（completion 1,320）；
  **qwen3.6-plus**（题面基准模型，已核实真实存在于百炼）：4/5，总 token
  17,733（completion 11,359）。同错同对，错误是系统性的；
- **双模型同错 reg_s_001（官方样例原题，漏选 C）**：推理显示模型严格依文档
  ——它指出仅有第四十一条的"弹性标准"（可能影响独立客观判断的关系）不足
  以确证独立性障碍，拒绝过度推定；而官方答案 C 依赖对该条的宽松读法。
  **定性：脚手架文档过薄（治理准则只给了 41 条）导致 C 选项证据欠定**，
  不是模型失误——qwen-plus 对同主题的单选题（reg_s_004）答对了。
  **处置**：脚手架 v1 扩充《治理准则》独立董事章节原文；同时此案例留作
  M4「证据层」的第一个真实素材（模型要的是更多文档依据，不是更强的猜测）；
- **qwen3.6-plus 是思考型模型**：completion 占总量的 ~64%（11,359/17,733），
  同题消耗约为 qwen-plus 的 2.2 倍。赛题 token 统计覆盖全部输出——
  **思考 token 计入 500 万预算**，模型选型时"更强模型"要过这道算术题；
- 官方样例选项 D 引用的「第77条授权」与 2023 版官方原文对不上（该版
  七十七条为会议记录条款），已在 fixture README 记录，脚手架以官方原文为准。
