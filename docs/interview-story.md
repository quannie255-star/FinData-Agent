# 面试官视角：我希望面前是一个怎样的项目

> 建立于 2026-09-23。这份文档回答一个具体问题：**如果我是面试官，我想看到什么。**
>
> 它的用途有两个，**顺序不能颠倒**：
> 1. 先当**检验标准**用 —— 决定你要补什么（与 `docs/product-goals.md` 配合）；
> 2. 再当**讲述脚本**用 —— 决定你怎么讲。
>
> ⚠️ 后者的前提是前者。**一个项目不会因为讲得好而变得扎实，但一个扎实的项目会因为讲得散而被低估。**
>
> 全文标注：`[已验证]` = 现在就能扛住追问；`[现在还没有]` = 必须补，别在面试里声称。

---

## §0 我的评判顺序（先说这个，因为它决定你要准备什么）

面试里我只有很短的时间，所以我会按**固定顺序**问五个问题。**顺序本身就是评分标准**——
每答不出来一层，后面的我就不问了。

| 顺序 | 我会问 | 我在听什么 | 答不出来的后果 |
| --- | --- | --- | --- |
| 1 | **你解决的是谁的什么问题？** | 能不能一句话让我听懂，且这句话里没有大词 | 我判断你没想清楚，后面全部降级为"跟着教程做的" |
| 2 | **你怎么知道它有效？** | 有没有**基线**、有没有**单位**、数字是实测还是估的 | 我判断你不具备量化判断力 |
| 3 | **你怎么知道你没骗自己？** | **有没有自己推翻过自己的结论** | ← **绝大多数候选人在这里交白卷。这一问是分水岭。** |
| 4 | **你放弃了什么？为什么？** | 取舍有没有理由，理由是不是"没时间" | 我判断你没有判断力，只有执行力 |
| 5 | **如果给你 10 倍时间和资源，你做什么？** | 你知不知道天花板在哪 | 我判断你看不到自己项目的边界 |

**我最怕看到的（反面清单，比正面清单更省你时间）**：

- 「提升了 40%」——**没有基线**。40% 是相对谁？什么口径？
- 功能罗列（"我用上了 RAG / LangGraph / MCP / 多智能体"）——**技术栈不是项目**。
- 数字来源答"我记得"——**那我默认它是编的**。
- 被追问一次就改口——**说明原本那个数字不是算出来的，是猜的**。
- 全程没有任何一处是"我原本做错了"——**要么你没做真实验，要么你不敢说，两种都扣分**。
- 「赋能」「打通闭环」「端到端」这类词——**如果没有可验证定义，它就是装饰**。

## §1 我希望看到的项目，长这样（"如果能重来"的画像）

六个特征，缺一个我都能接受，缺三个我会认为这是个课程作业：

1. **一句话能说清的问题**，且这句话里没有形容词。
   > 不是"做一个可信的数据分析平台"，而是"判断这条 agent 轨迹能不能拿去训练"。
2. **一个可被第三人复核的数字**：陌生人按文档重跑，能得到同一个值。
3. **一条自证的证据链**：报告里每个数字都能指到一份归档产物，而不是指到你的记忆。
4. **一份"我知道它哪里不行"的清单**——具体到编号与数字，不是"还有优化空间"。
5. **一个明确的取舍**：主动放弃过什么，并给出理由。**"不做清单"比"功能清单"更能说明水平。**
6. **一次自我推翻**：你曾经得出过一个结论，后来发现它是假的，你改了，并说清是怎么发现的。

> 第 6 条是我最看重的。**因为它无法伪造**——敢展示这个的人，说明他有真实的测量过程，
> 否则他根本发现不了自己错了。

排序依据只有一条：**被追问第二下会不会崩**。不是"听起来多厉害"。

### 2.2 听起来亮、但会被一刀捅穿的（**别在面试里主动说**）

| 说法 | 为什么会被捅穿 | 该怎么改口 |
| --- | --- | --- |
| 「工具清单从 27 个精简到 4 个，**质量不降反升**」 | **这条已经作废**：它出在含答案卡的语料上、用的是弱判据，而泄漏**偏向短清单臂**。干净语料重算 `exact_hit` 9 vs 7，**k=2 < 6 ⇒ 本对照没有分辨力** | 只说 token：**−52.0%，符号检验 p=2.46e-07（30 正 / 2 负）**；质量侧说"**没测到差异，且这对对照没有分辨力**" |
| 「裁剪返回内容能省 88.7% 字符」 | 字符省 ≠ token 省（88.7% 字符 → −25.2% token）；而且**报"省了 X%"必须同时给调用数与返回总量**（`hint` 臂每次进上下文最少，却让调用 56→81、返回总量 +53%） | 报实测 token 侧，并同时给三样：**省了多少、调用数、返回总量** |
| 「我用 MCP / LangGraph / 多智能体做了个 agent 平台」 | 技术栈不等于项目；而且这个项目**已经主动降级**了老赛道（占 62.6% 代码） | 讲**为什么降级它**（见 §5.3），这比讲它做了什么更值钱 |
| 「真实数据规模」 | 47 台真实 MCP server 是真实的，但**目标是 100–200 台**；任务仍是自撰的 32 道 | 主动说出这两个边界，**并说出你打算怎么补** |

> 这一节的用处：**主动把 2.2 说出来，比被抓出来强得多。**
> 面试官一旦自己发现你在夸大，后面所有数字他都会打折。

## §3 它叙述的是什么故事

一个项目要讲三层：**内核 → 弧线 → 元故事**。三层都在，才叫"故事"；只有一层，叫"说明"。

### 3.1 内核（一句话，没有形容词）

> **Agent 系统里最贵的错误，是拿一个"我没有证据"的判断，去执行一个有代价的动作。**

数字：重复上下文占 agent 账单约 **62%**；MCP 工具元数据占窗口 **40–50%**；
工具选择准确率在 50/200/740 个工具下 = 84–95% / 41–83% / **近 0**；
Gartner 预测 **>40% 的 agentic 项目 2027 年底前被取消**，首因是成本。

### 3.2 弧线（三次换域，同一个内核）

```
v1  这个数字能不能引用        （数据可信）
     ↓  同一个动作：停牌（合法缺失）vs 漏采 → 结论相反
v3  这条轨迹能不能喂训练      （数据质检）
     ↓  同一个动作：agent 漏填 vs 数据源 schema 缺陷 → 处置相反
v4  这段内容该不该进上下文    （上下文经济学）
```

**放大的方式不是换题，是换域而内核不变**——这是项目叙事里最有说服力的一点，
因为它证明的是**方法论可迁移**，而不是"我会某个工具"。

### 3.3 元故事（最该讲、最少人讲的那层）

> **这个项目真正的产出不是代码，是一套判定纪律和一份能被别人复核的证据链。**

支撑它的具体形态：

- 每个数字都能指到 `examples/` 里的归档，**不是指到某个人的记忆**；
- 产物里自带口径（`manifest.note`），口径不活在文档里；
- 对照实验的"只有一处不同"**由产物核对**，不一致就 `exit 2`；
- 报"没差异"时必须同时报**这对对照有没有分辨力**；
- **主动删掉过自己写好的探针**（因为它测的是数据源的表示层约定，不是缺陷）。

## §4 你是怎么开发这个项目的（**过程本身就是资产**）

这一节是我作为面试官最想听的，也是多数候选人讲不出来的——他们只会讲结果。
**"我是怎么发现我错了"这个过程，比结果更能证明能力。**

### 4.1 五次自我推翻（每次都固化成了一条规则）

| # | 原本的结论 | 怎么发现是错的 | 固化成的规则 |
| --- | --- | --- | --- |
| 1 | 2162 条工具定义存在"类型/默认值冲突" | 抽 3 条读原文，核出该数据源 **89.1% 的 `default` 本就是字符串**（是方言，不是矛盾） | **命中被一两个重复形态主导 → 先抽 3 条读原文**；探针当场删除。"一个从不删规则的质检系统，指标只可能虚高" |
| 2 | 1286 条是 agent 漏填参数 | 发现 description 承诺了默认值而 schema 没标 `default`——**错的是数据源** | 新增第五档处置 `🔧 待修 schema`（根因在数据源，处置就作用在数据源上），**丢弃归零** |
| 3 | 前提敏感度实验"结论稳健" | 两臂数字**一模一样**——因为 patch 错了函数，实验根本没生效 | **对照实验必须先证明"两臂真的不一样"**；加断言先证明 patch 生效 |
| 4 | 一批标着 7B 的读数 | 漏了 `--model`，实际跑成 3B，差点把"跨模型差异"读成"噪声很大" | **"只有一处不同"必须由产物核对，不能由记忆核对**；核对五样：代码/模型/语料/工具清单/裁剪策略 |
| 5 | 「短清单质量不降反升」 | 语料里放着写着题目与判据的 `tasks.py`；换无答案卡的语料重算后 **k=2 < 6，无分辨力** | **"知道了泄漏"≠"处理了泄漏"**——判别澄清的一半，必须配一次"**换干净输入重算**" |

### 4.2 开发方式本身（可复述的四条）

1. **先写判据，再写代码**：每个结论先定"什么算它成立的证据"，再实现。
2. **把口径写进产物**：`manifest.note`、账单里的 `scope` / `reproducibility`，
   让口径跟着数据走，而不是跟着文档走。
3. **一份声明必须能被证伪**：脚本里每一句"唯一变量是 X"都要配一个核对动作，
   否则那句话就是口号（这条是被真实事故逼出来的：跑实验的 22 分钟里我提交了 4 次，
   同一臂的三次调用读到了三个不同的目录状态，而脚本还在打印"唯一变量"）。
4. **控制实验成本**：验证用的是**确定性数字**（token / 成本 / 成功率），
   **不需要 GPU、不需要训练**——这是"一人可完成"的前提。

### 4.3 你（作者）自己做的产品决策（面试官喜欢听这个）

- 产品形态选**开源 CLI**，不选 SaaS / 网关：常驻服务会把项目拖进并发、限流、SLO、部署，
  而收益是零——网关自己就会常驻。
- 云端模型按**最小调用量**跑一次，只用来回答"换大模型会不会翻结论"，**不作迭代调参**。
- 真实 MCP 语料从手写 27 个 → **47 台真实公开 server / 230 工具**，并接受"卡在推理侧窗口"这个新问题。
- **不把闭源付费 API 接进 CI**：那会让别人无法复现，正好否掉项目最强的那一项能力。

## §5 业务思考与权衡（要能讲出来的七条）

### 5.1 为什么是现在（需求侧，不可替代）

不是"我觉得可以优化"，而是四个可引用的观察，见 §3.1。
其中最关键的一句：**Gartner 的 >40% 项目被取消，首因是成本；而成本里最大的一块是重复上下文。**

### 5.2 谁付费、谁受益

三个人群，**主叙述只能选一个**（选多了等于没选）：

| 人群 | 痛点 | 为什么可能是第一用户 |
| --- | --- | --- |
| 自己搭 agent 的独立开发者 | 工具越加越多、账单涨、模型开始选错工具 | **能自己验证**（你自己就是用户）——最小口子 |
| 平台 / 基础设施团队 | 要给内部 agent 定预算与准入策略 | 需要组织信任，不适合做第一个用户 |
| 做 agent 训练数据的人 | 判断轨迹能不能喂训练 | 是 v3.0 那条线，已在做 |

### 5.3 明确不做什么（**"不做清单"比"功能清单"更能说明水平**）

| 不做 | 理由（要能当场说出来） |
| --- | --- |
| 不造网关 / 不写 proxy | 那是成熟、有人维护、要处理并发与鉴权的组件；造它等于进一场必输的军备竞赛，而我们稀缺的是**"能证明策略没伤结果"的闭环** |
| 不做 SaaS / 账号体系 | 有账号就有合规、计费、客服，都不产出洞察 |
| 不接闭源付费 API 进 CI | 依赖付费外部服务的 CI 别人复现不了，否掉最强项 |
| 不自研"模型路由" | 竞品已占此路且不是我们的差异；复刻其协议必须标注「协议仿真，不是本体」 |
| 不做 LLM 质量打分 | **用另一个模型给轨迹打分，是把不可验证引进裁判位**。我们用确定性量 |
| 不做 K8s / 多地域 / 99.99% SLA | 那是服务型产品的要求，硬套就是过度设计 |

### 5.4 差异化的缝隙在哪（这是最容易被问倒的一问）

机制层（找没用过的工具、少发定义、检索注入、成本面板）**已经全部商品化**
——Langfuse / Latitude 已经把 *Unused* 做成徽章了。
所以**缝隙不是"裁剪的点子"，而是"能证明裁剪没伤结果的闭环"**：

1. 证据来自 **trace 的引用观测**（不是合理性推断）；
2. 有**配对验证闭环**（同一批任务、两臂、可核对）。

> 竞品的对应弱点：`tamaratran/fast-jev-compaction` 把工具结果**换成一行提示**
> ——**它看不到返回内容，判的是合理性，不是证据**。

### 5.5 口径自律（这一条会让你在同类候选人里明显不一样）

- **token 只占可变运行成本 20–25%**（McKinsey QuantumBlack；人工复核占 70–75%）
  ⇒ **不把"省 25% token"说成"省 25% 钱"**。
- **字符省 ≠ token 省**（88.7% → 25.2%），只报实测 token。
- 报"省了 X%"**必须同时给调用数与返回总量**（裁剪会让模型改变行为，"省"不是单调的）。
- 结论适用范围：**token 侧可迁移**（由上下文结构决定），**成功率侧只在本地 7B/3B 口径成立**。

### 5.6 每一条结论都要写"成立条件"

这是本项目的写法，建议你保持：

> 「`head` 裁剪省 23–25% token；质量侧在 7B 的**代码一致子集**上 `exact_hit` k=7（有分辨力）且 p=1
> ⇒ **没测到伤害**。**不能说"证明无害"**；3B 上 k=4，**测不出**。」

一句话里同时有：**数字 / 口径 / 效力 / 不能说什么**。四样齐了才叫结论。

### 5.7 承认的清单（比报好数字更有用）

面试里最该主动交的三件（+ 现在要加的第四件）：

1. 人工一致性 κ **没做**（只有机器 vs 机器 κ=+0.7417，n=13）；
2. 超时归因**只有一个信号**，且**刻意不修**（本批 0 命中＝未验证）；
3. held-out 63.6% vs 门禁 ≥0.9 的**红灯不划掉**；
4. **R5.2 的质量侧只有 3B 批完整可用**，7B 只剩 `fx↔ch` 一格（因为一批跑到中途我改了仓库，代码指纹裂成两组）。

## §6 三个时长的讲法

面试实际只有三种时长，**分别准备，别一套讲到底**。

### 6.1 30 秒（自我介绍里带过）

> 「我做的是一件很具体的判断：**agent 的运行轨迹里，哪些内容不该进上下文。**
> 因为重复上下文占 agent 账单约 60%，而 Gartner 说四成 agent 项目会因成本被砍。
> 我的做法是不造网关，而是喂进轨迹、**吐出一份现成网关能吃的策略**，
> 再附一份'这个策略有没有把结果做差'的配对验证报告。」
>
> ⤷ 停顿，等对方挑一个方向再展开。**不要主动报数字**，等他问——他问哪个，说明他对哪块有兴趣。

### 6.2 3 分钟（"讲讲你这个项目"）

骨架**四段，每段一句**：

1. **问题**：一句话内核（§3.1）；
2. **怎么验证**：确定性数字、配对实验、工具是确定性的（§4.2）；
3. **我推翻过什么**：挑 §4.1 里的**第 5 条**讲（语料泄漏），因为它最完整：
   发现问题 → 量化规模（16 条查询里 10 条被污染，+45,514 字符）→ 换干净语料重算 →
   结论从"不降反升"变成"没有分辨力" → 固化成流程；
4. **我不做什么**：网关 / SaaS / LLM 打分，各一句理由（§5.3）。

### 6.3 追问 20 分钟（最硬的两个问题 + 答法方向）

**Q1：「你的结论会不会换个大模型就翻了？」**
→ 诚实版：**目前所有质量侧结论都只是本机 7B/3B 口径**；这正是下一步（云端模型按最小调用量跑一次）。
→ 加分点：说明**token 侧可迁移**的理由（由上下文结构决定，不由模型决定）。

**Q2：「你说质量没变差，凭什么？」**
→ 正确答法**不是**"测出来没差"，而是：
「**我做了分辨力下限检验。** 这对对照的 k=7（超过 6 这条线），所以它**有能力**发现差异；
在这个前提下 p=1 ⇒ 可以说'没测到伤害'。而在另一批（3B，k=4）上我**只能说不显著**，
**不能说等效**。所以我报的是'没测到'，不是'没有'。」
