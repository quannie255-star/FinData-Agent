1怎么用：三个入口

入口 A · 个人可用版（最直观，能当场演示给别人看）

uv sync                    # Python 3.11+
# .env 写入 FINDATA_DASHSCOPE_API_KEY=...（阿里云百炼控制台）
uv run findata-finqa-app   # → http://127.0.0.1:8100

「我的文档」标签页：上传 PDF / Word(docx) / TXT / Markdown（≤50MB）→ 自动转换建索引 → 自由提问。 答案只依据你的文档、带出处引用；文档里没有的会明说、不编造。文件只存本机 findata_userdata/（已 gitignore）。

如实边界（演示时主动说）：① 无鉴权，只在本机用，不要暴露公网； ② 每次提问是真实 API 调用（数千 token，几分钱）；③ 英文 10-K 检索弱于中文条款域（外部基准实测）。

入口 B · 金融数据可信引擎（离线、零 API key，5 分钟见效）

uv run python scripts/daily_pipeline.py --skip-ingest        # 出带四档徽章日报
uv run findata-trust-report 你的任意.csv -o report.md --html report.html

任何 CSV / Excel / DuckDB / SQLite 表都能出带徽章报告（✓ 基线通过 / ⚠️ 仅借鉴 / ✗ 不可用）。 没有 schema 也能跑。这一条是「陌生人能不能跑起来」的入口。

入口 C · 看数字从哪来（面试官追问时用）

uv run pytest --collect-only -q      # 791
uv run pytest && uv run ruff check .  # 全绿

所有对外数字的归档在 examples/；复现命令在 eval/fixtures/afac_scaffold/README.md。CI 链路：lint → pytest → e2e smoke → eval-gate。

面试主线（docs/interview-story.md §0 的五问，按这个顺序准备）

  • ① 你解决的是谁的什么问题（一句话，无形容词）→ 「金融长文档问答里，检索找不到 / 判定被干扰 / 压缩丢事实」
  • ② 你怎么知道它有效 → 基线 + 单位 + 口径；数字指到 examples/ 归档
  • ③ 你怎么知道你没骗自己 → 主力素材：错题形态迭代链（六环 + 三次折返）。 这一问是分水岭，绝大多数人交白卷。
  • ④ 你放弃了什么 → 不做网关 / 不做 SaaS / 不做 LLM 打分 / 不做模型路由（各一句理由）
  • ⑤ 给你 10 倍资源做什么 → 题量提分辨力、云端模型口径、真实长文档规模
能当场报的四条稳数字： ① 反复迭代后 90% → 隐含 100%（50/50），且每个拐点都归因到具体机制； ② 分层压缩把记忆臂从 77.4 ± 3.2% 恢复到 96%（「不可逆信息不动」的验证）， 同时如实报告它 token 仍更贵； ③ 791 例测试 + CI 门禁（含真实数据回放 golden 9 例逐条断言）； ④ 英文域检索三臂消融：向量臂是杠杆（recall@8 16.16% → 41.41%）， 但等权 RRF 融合反而弱于纯向量（21.21%）—— 能讲清「为什么融合没赢」（两臂强弱悬殊时等权融合稀释名次位）比报一个漂亮数字更难伪造。

四句不能说（会被一刀捅穿）

已撤回「短清单质量不降反升」——那批跑在含答案卡的语料上、判据弱、 泄漏偏向短清单臂；干净语料重算后 k=2 < 6，本对照没有分辨力。 质量侧只能说「没测到差异，且这对对照测不出」。

单位串了「字符省 88.7%」≠「token 省 88.7%」（实测 −25.2%）。

口径错「省 25% token」≠「省 25% 钱」——token 只占可变运行成本 20–25%， 人工复核占 70–75%。

减分把技术栈当项目讲（「我用了 RAG / LangGraph / MCP / 多智能体」）。 要讲「为什么不用」，而不是「用了什么」。
