### 关于「数据合成」这条，我们的选择是不做，理由要能讲

JD9 第 1 条写的是「数据合成」。我们**没有**合成数据，做的是从真实公开
语料里**筛出可训练样本并导出标准格式**。理由不是懒：

- 自造的失败样本形状必然贴合自己写的规则 → 合成集 100%，换成从没参与
  调参的 held-out 集**63.6%**。这个数字就是循环论证的量化代价
- 面试官追问「你合成的样本怎么保证像真的」，答不上；而**真实语料不需要
  回答这个问题**

代价：`数据合成 2/10` 这个关键词只能靠"筛 + 导出 + 格式化"去沾边，不能
说"我会造数据"。**取舍讲清楚比硬凑一个合成器强。**

## 5. 明确不补的东西（以及为什么）

| 不补 | 理由 |
| --- | --- |
| Spark / Flink / Hive | 单机项目硬补 = 玩具，面试一问"你们集群多大"就穿。补了反而暴露短板 |
| RAG / 向量检索 | JD 里出现 2 次，但 findata 用不上。硬塞会毁掉"探测与判断分离"铁律——**这条我之前就否决过，不因为 JD 出现就改口** |
| A/B 实验 / 统计建模 | B 类赛道的核心，但那是另一个项目。与其两头都要，不如 C 类打透 |
| 前端全栈 | JD8/10 要，但全栈是另一个项目的工作量，会稀释主线 |

**代价：放弃 B 类（JD 2、4）**。这两个岗位建议靠 SQL/Python 基本功 + 别的项目/课程经历去凑，findata 不负责覆盖它们。
