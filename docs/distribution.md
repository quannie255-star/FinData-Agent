# 分发与止损计划（v2.2.0 起生效）

> ROADMAP R3 的最后一环。launch 后 30 天，**唯一指标 = 是否有陌生宿主
> 真实调用了 trust 接口（或集成了 trust-report）**。有 → 加领域包横向
> 扩展；没有 → 停线复盘。本文定义 launch、测量方式与决策门，
> 防止"止损"变成拍脑袋的情绪决定。

- [ ] README 为 v2.2 增强模块定位（已完成，2026-09-17 重写）

## 二、唯一指标与测量方式

**指标**：是否存在 ≥1 个**可验证的陌生宿主集成**——不是 findata 维护者本人、
不是熟人帮忙测试，而是能给出证据的外部使用（issue 里描述接入方式、PR、
可复现的调用记录）。

测量只用手工人肉方式，**模块内不做任何遥测**——一个讲"可信"的项目偷偷
上报使用数据是自我否定。信号源按可信度排序：

| 信号 | 哪里看 | 可信度 |
| --- | --- | --- |
| issue/PR/邮件描述真实集成 | GitHub | 最高（直接证据） |
| ghcr 镜像 pull 次数（非本人/CI） | ghcr.io 包页 | 中（无法区分用途） |
| star / fork 增长 | GitHub | 低（兴趣 ≠ 使用） |

**明确不算数的**：本人拉取、CI 拉取、熟人测试、AI 会话里的演示。
宁可 30 天后拿到一个诚实的 0，不要一堆自欺的 +1。

## 三、30 天后的决策门

### 分支 A：有 ≥1 个可验证的陌生集成 → 加领域包

优先级按第一个真实用户的数据域定，不预设。新领域包的准入标准
（沿用 A 股包立下的模式）：

1. 该领域存在"形态相同、结论相反"的归因问题（否则通用包就够，不需要领域知识）；
2. 领域知识可查表化（日历/事件表），或可由仓库自证（截面共动式）；
3. 评测先行：先写该领域的验收门禁进 ROADMAP，再动手。

### 分支 B：0 个陌生集成 → 停线复盘

回答三个问题并写成 `docs/reviews/` 复盘（与归因复盘同规格）：

1. **定位错了还是渠道错了？** 对比页/日报/接入演示哪个内容带来过最多反馈？
2. **宿主为什么不用？** 是接入摩擦（MCP 配置门槛）、价值不感知（徽章没打中人）、
   还是赛道本身不需要（宿主自带质量检查）？
3. **哪部分资产在任何转向下都成立？** 归因架构、评测门禁方法论、
   带徽章报告的形态——这些是简历与后续项目的底座，不随本项目止损而贬值。

止损 = 停止投入新功能，**不是删库**。封存的评测资产与归档结论
（`examples/`、`docs/reviews/`）继续可用，PITCH 数字全部有归档背书。

## 四、窗口期内的克制（不做清单）

- 不加新功能、不开新 Phase——唯一任务是把已有的东西送到能被找到的地方；
- 不做遥测、不做 waitlist、不做"预留接口"式的假开放；
- 不因为焦虑而改定位：30 天没到，任何"要不要转向"的念头都先记进本文档
  末尾，到期一起看。
