## 发现：旗舰 MCP 工具对陌生人默认会报错

## 主赛道选定：Agent 训练数据的质检与过滤（用户拍板"你挑一条"）

**选定 C 类的 Agent 数据工程，落点进一步收窄到「轨迹的质检与过滤」**。

关键外部事实（2026-09-18 搜证，非记忆）：Langfuse / LangSmith / Arize /
Braintrust 做的是 tracing + 打分 + 人工标注闭环，目标是**改进 agent**；
独立对比文（Inference.net 2026-06）原话：「两者都擅长存储与检查单条
trace，但都不告诉你几千次运行里究竟是什么一直在出错」。
而 JD9 要的是**生产训练数据**：从海量轨迹筛出可用正负样本。目标不同。

**核心命题（与 findata 原有肌肉 100% 同构）**：
轨迹的成功/失败是**形态**，能不能当训练样本是**结论**——
- 表面成功但路径错误（蒙对）→ 不能当正样本，会教坏模型
- 表面失败但归因于环境（沙箱超时）→ 不该当负样本，会浪费数据
这就是"停牌 vs 漏采"换到轨迹域。

**不做的**：不跟 Langfuse/LangSmith 抢 tracing 与看板；RAG/Spark/A/B 继续不做。
A 股降级为**领域包 1**（保留作"归因不是只会一件事"的证据），不是放弃。

### 落地（docs/ROADMAP.md 顶部重定向节 + Phase R4；AGENTS.md 加「当前主赛道」）
新增 `src/findata/agentops/probes.py`：5 探针，严格执行**探测与判断分离**
（与 dq/probes.py 同铁律）。degrade / abort / retry_storm /
**ungrounded_slot** / silent_mismatch。

### ungrounded_slot 探针（本轮最有价值的一个）
不依赖任何 golden 标签，查「这个值在问句里有没有出处」→ 生产环境可用。
三道误报防线（第一版误报 42/48，全靠这三条收窄）：
1. **不查 symbol**——问"中芯国际"却要求问句里出现 688981 是荒谬的，
   映射本身就是出处；
2. **整月展开放行**——"8 月"→2025-08-01~08-31 是项目约定（合法推导）；
   只在问句给了具体日时才要求每个日期查得到出处；
3. **纯中文数字问句标 unverifiable 而非指控**——"二〇二五年九月四日"
   模型其实读对了，只是问句没有阿拉伯数字。查不出处 ≠ 有幻觉。

## R4.2 合成集 + 首个有 ground truth 的归因评测

新增 `src/findata/agentops/synth.py`：7 类（ok / param_error / tool_missing /
env_timeout / retry_loop / hallucinated_date / lucky_guess），
根因**写进 golden**，确定性（seed 固定可复现）。
`scripts/run_synth_eval.py` 跑三件事：证伪检查 → 归因准确率+混淆矩阵 → 处置分布。

### 三个数字，只有第三个算数
| 集 | 准确率 | 说明 |
| --- | --- | --- |
| 常规集 canonical | 100% | **循环论证**：规则是我写的，样本照着规则造，拿规则原话考规则 |
| dev 改写集 | 100%（修前 75.7%） | 已用于调关键词，是调出来的，不算泛化 |
| **held-out 集** | **63.6%** | 从不参与调参，**这才是泛化能力** |

教训（与"拿模板题集证明规则解析不差"是同一个坑）：**自己造的样本证明不了
自己的规则**，必须留一份从没参与调参的 held-out，且不许照着它改规则。

### held-out 暴露的真问题
tool_missing 0/20、env_timeout 0/20 —— 关键词匹配换个说法就全崩
（"the requested function is not registered"、"deadline exceeded" 都认不出）。
**这就是关键词归因的天花板**，也直接指向下一步：错误码结构化 / embedding
相似度 / LLM 分类，而不是继续往关键词表里加词。

### 处置判定（第二维，与根因分开）
`triage.verdict()`：✓正样本 / ⚠️需人工 / ✗丢弃 / ⊘不算失败。
根因与处置分开的理由：同样失败，沙箱超时不该当负样本（环境问题），
参数写错才该丢（能力问题）；混成一维就没法单独调过滤规则。

测试 389 passed（+5），ruff clean。

### 查出来的新证据：`default` **贴错了位置**（比"漏标"硬一个量级）

`calculate_electric_field`（`row 65`）原文：

```json
"charge":      {"type": "int",   "default": 8.854e-12},
"distance":    {"type": "int",   "default": 8.854e-12},
"permitivity": {"type": "float", "description": "...default is 8.854e-12."}
```

8.854e-12 是**真空介电常数**，不可能是库仑计的电荷量（还是 int 型）的默认值。
→ 不是"作者忘了写"，是**值写在了错的参数上**。
全量这类只有 **2 个参数位**（`permitivity` 258 次 / `confidence` 83 次），
其余 19 项是纯措辞。**处置必须分型：19 项"补上" vs 2 项"移动"**——
统一成"补 default"，数据源方会给两个参数同时标 8.854e-12，改得更错。

### 三个"以为自己发现了、其实抓错了"的时刻（这轮最值钱的部分）

1. **类型/默认值冲突探针**：纯机械规则，不依赖任何 description 措辞，
   全量 2162 命中——差点就进报告。抽三条原文发现**该数据源 89.1% 的
   `default` 本就是字符串**（`type: int` + `default: "10"`），是表示层约定。
   **探针当场删除**，把这次自我否定写进报告第八节。
2. **对称默认值**：第一版"值错位"探针只查"描述称的值出现在别的参数上"，
   把 `latest_tweets`（三个参数都 `default: 10`）这类**对称情况**全报成错位
   （假命中 1617）。收紧条件：**宣称方自己必须没有 `default`**。
3. **自己 docstring 里的过度表述**：「没标 default 就必须显式传」被我写成
   JSON Schema 通行口径——实则该数据集 `required` 字段为 0，
   **这纯粹是我设的口径**。另 `_DEFAULT_HINT` 把"标了 optional"也报成

### 找到的热度方向（有硬数字）

- **Outcome Monitors**（南密西西比大学，2026）：拦截工具返回异常 → 附加**非阻塞
  诊断回执 + 恢复工具建议**，不改执行不阻断 → **ToolMaze 10.9% → 28.1%**；
  τ-bench retail **+14.0 / +12.0 分**。原话：「**diagnostic receipts with actionable
  recovery affordances drives the bulk of these gains**」
- **AgentDebugX**（arXiv 2607.18754）：Detect→Attribute→Recover→Rerun 闭环，

  但不减少 semantic misuse」**——**这正是我"形态相同结论相反"的学术版本**
- **Constraint Tax**：五种 Tool Suppression 分类 TS-A~TS-E

**这三篇论文解决了我项目最大的空洞**：本机能测出来。
10.9%→28.1% 不是 2% 抖动，是失败→成功的跃迁，RTX 4060 + 7B 够用。

### 我的独特缝隙（没被覆盖的地方）

| 项目 | 输入 | 输出 | 方向 |
|---|---|---|---|
| mcp-lint 们 | 静态定义 | "有 3 个 warn" | 静态 → 定义方 |

taxonomy 是**轨迹失败模式**（规划/记忆/交接），不是 **schema 缺陷模式**（值错位/缺声明）；

（可靠性：中。覆盖了 GitHub/npm/arXiv，不排除未搜索到的实现。）
