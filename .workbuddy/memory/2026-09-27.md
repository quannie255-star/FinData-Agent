## 顺带挖出的两件事

1. **全项目最有说服力的资产此前完全看不见。** `logs/` 被 gitignore ⇒ 那段"考试→修复→没回退"
   的历史在 GitHub 上一个字都没有。这是本轮最该修的，且最便宜。
   - 给 `.gitignore` 开了**有理由的**例外：`logs/*` + `!logs/daily/`。
     注意必须写 `logs/*` 而不是 `logs/` —— **git 不会进入被整个排除的目录**，那样 `!logs/daily/` 无效。
   - 日志只是 112K / 30 个文件，体量不是问题；`reports/daily/` 仍排除（那才是可重生成的）。
2. **09-15 19:17 调度器首跑崩过，而且只在调度器会话里复现。**
   - `subprocess._readerthread` → `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xb2`
     → `daily_pipeline.py:65` `TypeError: 'NoneType' object is not subscriptable`。
   - 根因：父进程按 UTF-8 读子进程输出，而子进程在调度器给的**非 UTF-8 控制台**里输出 GBK。
   - 修法（代码里已留注释「管线不许因日志崩」）：`text=True, encoding="utf-8", errors="replace"`。
     **宁可乱码，不许崩** —— 无人值守管线的正确取舍。
   - 编码不一致是有机制的：管线自己写 UTF-8，而 `schtasks.log` 是**调度器 wrapper 的 `>>` 重定向**
     写的 GBK。**用 UTF-8 读它会直接报错**（不是损坏）。

## 用户拍板：收敛到金融侧，暂停升级规划

⇒ 交付 `docs/final-scope.md`：**决定 + 最终目的 + 五个目标词的可验收判据 + 冻结清单 + 未决四项**。
`docs/product-goals.md` 顶部加了指向与修正块（两份冲突以 `final-scope.md` 为准）。

### 最终目的（我的答案）

> **把「这个数字能不能用」从口头判断，变成一份带证据链、可被第三方核查的产物。**

关键是要同时说清反面：**它不生产数字，只回答"可不可信、为什么"**（差异化在归因不在检测）；
换域两次是「这套判断不是只会一件事」的**证据**，**不是两个额外产品** ——
而**三个域都做成半成品 = 三个都不是产品**，这才是必须收敛的原因。

### 五个目标词的拆解（写进文档时全部带证据）

- **跑过真实数据：已达成，是全项目最强项**（akshare / 25 标的 / 28,652 行 / 10 个运行日 / 前后对照）。
  这条是重构中最容易弄丢的 ⇒ 纪律：**宁可慢，不要让"连续运行 + 前后对照"断掉。**
- **工程成熟：部分。** 硬门槛是 **无 `LICENSE` 且仓库公开**（`private:False`、`license:None`）——
  别人看到也不能合法复用，成本最低、收益最直接。
- **高可用：部分。** 先给对定义 —— 对"每天跑一次的管线 + 一个 CLI"，**不是 99.99% SLA**，是四件事：
  ①不会挂死（`daily_pipeline.py` 子进程**无 timeout**，这是当前唯一"未开始"项）
  ②不会毁用户状态 ③坏了能诊断（**已达成**，schtasks.log 里那次崩溃就是证据）④部分失败如实报。
- **有业务思维：最弱，且不能靠写文档补。** 只能靠"至少一个不是你的人，在你的产物上做过一次决定"。
- **不是 toy：只有一个判据 —— 有别人跑过。** 无法自己声明；路径 = 补 LICENSE → 离线 5 分钟示例 →
  陌生人用他自己的数据跑一次 `findata-trust-report`。

我此前（和 MEMORY 里）写"**主赛道在 CI 里 0 门禁**"——**过于绝对，是错的**。复核 `test.yml`：
它其实拦得不少（`ruff check src tests` / 全量 pytest / **e2e 真起 uvicorn + 4 路由断言** /

① **没有一条门禁是为主赛道写的**；② **`scripts/`（8,663 行，主赛道交付载体）不在 lint 范围**；
③ **`ci.yml` 那条 `ruff check .` 只在 `main`/PR 触发**，而主开发直推 `master` ⇒ 平时不跑。

⇒ 教训同 §2.1③：**"0 门禁"这类绝对断言，报之前要先读一遍 workflow 文件**。
而且这条修正对用户的方向判断是**有利**的：金融侧不只是唯一在运行的，也是唯一有真门禁的 ——
