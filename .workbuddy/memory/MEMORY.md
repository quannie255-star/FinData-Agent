## 1. 实验台最终口径

### 1.1 R5.0 定义侧（token 侧是全项目最强结论）

32 任务 × 2 臂，唯一变量 = 工具清单长度（27 vs 4）。**干净语料（210 文件 / `e4deb476c30c93e4`）实测**：
prompt_tokens 222,401 → 106,843（**−52.0%**，符号检验 **p=2.46e-07**，**30 正 / 2 负**）；反例 **2/32**
⇒「短清单一定更省」是错的。受控探针实测定义 token 差 **1,664/次** vs 端到端 1,435.3/次（86%）
—— 两条独立路径对上但**不是恒等式**。

**⚠ 质量侧已被自己推翻（09-23）**：`exact_hit` **9 vs 7，k=2 < 6 ⇒ 无分辨力**；弱判据 11 vs 11（k=4, p=1）。
**原报"不降反升 7→13 / p=0.03125"作废** —— 那批跑在**含答案卡**语料上、用**弱判据**，且泄漏**偏向短清单臂**（§2.9）。

### 1.2 R5.2 返回裁剪（**只认"代码一致 + 语料一致"的子集**）

四档：`fx` 不裁 / `ch` head（合理性判断，常数 500 字符）/ `ci` hint（整段换一行**提示**，
**协议仿真不是 Jev 本体**）/ `cp` cap（证据型，上限学自另一批 trace 的 p90）。

**3B / 四臂全同代码 `ef9f3bca` + 同语料 + 无答案卡（唯一完整可用的批）**

| 对照 | token 降幅 | 符号检验 p | `exact_hit`（都中/仅A/仅B） | k | McNemar 双侧 | 单侧 |
| --- | ---: | ---: | --- | ---: | ---: | ---: |
| `fx↔ch` head | −23.4% | 0.0002441 | 2 / 4 / 0 | 4 | 0.125 | 0.0625 |
| `fx↔ci` hint | −21.5% | **0.2649** | **0 / 6 / 0** | **6** | **0.03125** | **0.01562** |
| `fx↔cp` cap | −25.1% | 0.01182 | 2 / 4 / 1 | 5 | 0.375 | 0.1875 |

**7B 唯一可用的配对只有 `fx↔ch`**（两臂同代码）：token **−25.2%**（p=0.004344）；
`exact_hit` 都中 4 / 仅 fx 4 / 仅 ch 3 ⇒ **k=7 ≥ 6（有分辨力）且 p=1**。

**三条结论（按可辩护程度排序）**：
1. **「少给内容」与「不给内容」不是程度差异，是两种东西。** `hint` 在 3B 上 **k=6、6 个不一致对全朝 fx、
   0 朝 hint**（双侧 p=0.03125）；7B 单臂 `exact_hit` 1/32（fx 8/32）方向一致
   ⇒ **唯一跨两个模型复现且显著的质量结论**。且它 **token 侧 p=0.2649 不显著** —— hint 会让模型多调工具
   （返回总量 +53%），**"省"不是单调的**。
2. **`head` 省 23–25% token，质量侧"没测到伤害"**（仅限"7B 有分辨力子集"这一格）；**不能说"证明无害"**。
3. **`cap` k=5 测不出** ⇒ **"两次测不出"≠"两次都没事"**。

### 1.3 ⚠ 效力边界（缺一条就可能读错）

1. **7B `-fp` 批内部分裂**：`fx`/`ch`=`ef9f3bca`（625,281 字符）、`ci`/`cp`=`4b313ddb`（**629,723**）
   ⇒ **`fx↔ci`、`fx↔cp` 有两变量，7B 读数作废**；更早的 7B 四臂批**无代码指纹** ⇒ 代码轴无法核对。
   ⇒ 7B 的 R5.2 结论**只有 `fx↔ch` 一格能用**。
2. **`-fz` 批（214 文件，含答案卡）与 `-fx`/`-fp` 批（210，无答案卡）是两个语料**，读数不可混用。
3. **解码仍未固定**（无 seed、未压 temperature）⇒ 顺序定死：**① 先量噪声下界 → ② 再固定解码 →
   ③ 写进对照表**，不许颠倒（先固定再量只能量到 0，就不知道现在的结论里有多少是噪声）。

**噪声下界（已实测）**：7B 同配置两次 token 差 **0.8%**、逐 token 相同 **26/32**、质量 k=1；
3B 差 **0.1%**、相同 26/32、k=3。**噪声主要在"生成"不在"累积"**（prompt 0.8% vs completion 2.1–7.8%）
⇒ **报 token 必须说清 prompt 侧还是 completion 侧。**

## 2. 铁律

**2.1 三条判据**（①③ 的通用做法已沉淀成 skill `quantitative-claim-audit` 的陷阱 5/6/7，此处只留项目事实）。

**① 证据强度要分层：「值缺失」与「值放错位置」差一个量级。** 项目实例：
`calculate_electric_field.permitivity` 描述称默认 8.854e-12、自己没 `default`，而该值**标在 int 型
`charge`/`distance` 上** ⇒ 不是"漏标"（疏忽可解释），是"错位"（疏忽解释不通）。**分层直接决定处置**：
漏了→补上；放错了→移动。
**② 两种解释都成立时选可逆的动作，别打解释之争。** `required` vs description 谁优先？**不需要赢** ——
两种读法处置都落在"改 schema"。判据 = **丢样本不可逆、改 schema 可逆**；1 处 schema 缺陷影响 258 条样本，
修 1 处消 258 条歧义，丢 258 条什么都不解决。**处置风险等级应由证据强度决定，不该按类别一刀切。**
**③ 报数前先问：这个"冲突"是不是数据源的表示层约定。** 项目实例：类型/默认值冲突探针全量 2162 命中，
核出该源 **89.1% 的 `default` 本就是字符串**（方言不是矛盾）⇒ **探针当场删除**。
**一个从不删规则的质检系统，指标只可能虚高。**

**2.2 处置与措辞。** 处置五档（`agentops/triage.py`）：`✓ 正样本 / ⚠️ 需人工 / ✗ 丢弃 / ⊘ 不算失败 /
🔧 待修 schema`（第五档 = **根因在数据源，处置就作用在数据源上**）。处置选择还看 **①能否给出可执行动作
②队列长度**（5 条→人工队列是队列；349 条→逐条看等于没有队列，必须结构性修复）。措辞：「命中率」≠「发现率」；
**命中数 ≠ 错误数**；「未命中」≠「干净」（无执行反馈时"正确"观测不到）；变量名也是措辞（`n_bad`→`n_hit`）；
**口径写进产物本身**（`manifest.note`），别只活在文档里。

**2.3 门禁与可复现。** `tests/test_docs_consistency.py`：各文档测试数只能有一个值，且**必须等于
`pytest --collect-only` 真实收集数**（错数 354 实测在 6 处共存一个月；两份拷问文档刻意不在扫描名单）。
**可复现三元组** = `code_commit` + `rules_version`（改判定逻辑必须动 `triage.RULES_VERSION`）+ `data` 指纹
（公开数据集会被作者修订）。**代码指纹**：账单 `code_commit` 取自语料根（冻结快照），**真正执行的代码在工作区**
⇒ 补 `executed_code`（`corpus.manifest_of` 覆盖整个 `src/findata/` + 入口脚本）；
**相对路径是指纹的一部分**（它就是要发现改名）。

**2.4 对照实验的元坑（同一个错误犯了三次）。** ① patch 错函数（前提敏感度实验 patch 了
`_description_claims_default`，实际走 `default_claim()`+`misplaced_defaults()` ⇒ 两臂一模一样，
"结论稳健"差点是假结论；修法：**加断言先证明 patch 生效**）② **漏 `--model`**（一批"7B"实跑成 3B，
差点把"跨模型差异"读成"噪声很大"）③ **边跑边改仓库**（§2.11）。
⇒ **"只有一处不同"必须由产物核对，不能由记忆核对**；核对五样：**代码指纹/模型/语料指纹/工具清单/裁剪策略**。
**臂名是标签不是证据** —— 文件名会撒谎，账单的 `scope.model` 与 `reproducibility.executed_code` 不会。
`--require-same-corpus` / `--require-same-code` 是硬闸门（不一致即 exit 2）。

**2.5 拿本地仓库当语料：冻结 + 指纹化**（真事故换来；通用做法已沉淀成 skill `corpus-freeze-and-drift-check`）。
**事故**：第一臂跑的 22 分钟里提交 4 次 ⇒ 同一臂三次 `list_files` 读到三个目录状态，脚本还在打印
「唯一变量是工具清单长度」；事后核出 **4 处漂移 / 570 字符 / 覆盖率 18.7%**。本项目特有仍要记住的两条：
- **"冻结"由路径保证，不靠自律**（`git worktree` + `--corpus-root`）；**一句声明必须有产物能证伪它**，
  否则不是诚实说明是**口号**。账单指纹看"现在"的磁盘，`check_corpus_drift.py` 回看"当时"落盘的 trace
  —— 那次事故**只有后者能发现**。
- **盲区要写出来**：说「已核的有 4 处，未核的不知道」，不说「只漂了 4 处」；报漂移要同时报**方向**
  （四处全是 A 更小 ⇒ 结论偏保守，"没威胁结论"≠"可以不说"）。

**2.6 指纹口径：必须测"工具实际读到的东西"。** 字节哈希让主工作区 vs worktree **误报 53 个文件变了**
—— 实为 `core.autocrlf` 把 LF 写成 CRLF，而 `read_text()`（universal newlines）读到的**逐字相同**；
改成"归一化文本哈希 + 规模按**字符数**（与 `payload_chars` 同口径）"后 **53 → 0** ⇒ 与 §2.1③ 同类：
**先分清表示层差异，再谈内容差异。**（Windows 坑：`Path.write_text` 会把 `\n` 翻成 `\r\n`；
测试要构造 CRLF 必须用 `write_bytes`。）

**2.7 分辨力下限 = `2^(1-k)`**（k = 配对不一致对数）。**k ≥ 6 才可能有分辨力**（k<6 时最小 p ≥ 0.0625）
⇒「不显著」的正确读法是「**本对照测不出**」，既非"无差异"也非"等效"；**报"不显著"必须同时报 k**。

**2.8 同文件的并行编辑会互相覆盖。** 同一消息里给**同一个文件**发两处 Edit，第二处按旧内容匹配
⇒ **一处静默丢失** ⇒ **改同一个文件必须逐个发。**

**2.9 判据泄漏的两个面。** **答案侧**（`grading.has_exam_leak`）：冻结语料曾把 `tasks.py`
（**同时含 32 道题与 `must_contain`**）装进去 ⇒ 模型读它答案里就带上判据（实测 t23 整段讲 `tasks.py`
却引用了 `Task("t23", …)`）。指纹取窄（`must_contain` / `Task\(\s*"t\d\d"` /
`tags=\(\s*"(?:single|multi|cross)"`）—— **一个"泄漏"标记会直接剔数据，误标就是误删**；
泄漏答案 `failed_by="leaked"` 单列并**剔出各档统计**（不重跑：`runs-*.jsonl` 存了原文）。
**语料侧**（`contextbudget/leakcheck.py` + `scripts/check_corpus_leak.py`，exit 3 可进门禁）：判据 1 **路径**
（受保护路径 5 条）；判据 2 **内容**（与文件名无关 —— **实测抓到判据 1 漏掉的 2 个文件**：
`contextbudget/__init__.py`、`tests/test_contextbudget.py`）⇒ **凡想只靠一份手写清单下结论的地方，
都会低估泄漏面**；判据 3 **重放**（工具确定性 ⇒ 差异不含采样噪声；`summarize_replay` 单测钉住
**变小的查询不能拿来抵账**）。

**泄漏的量化后果（`[实测]`，无别处落盘）**：两快照 `ctxbench-frozen`（**214**/`00a95aea86927097`）vs
`ctxbench-frozen-noleak`（**210**/`e4deb476c30c93e4`）差集**正是那 4 个答案文件**
（`docs/r5.0-acceptance.md`、`tasks.py`、`contextbudget/__init__.py`、`tests/test_contextbudget.py`）；
mtime 09-20 19:54 < `-fz` 批 09-20 20:17 ⇒ **那批跑时答案卡确实在**。
16 条真实查询重放：**10/16 在含卡语料上返回更大，共 +45,514 字符**，单条最多 +4,696；
最极端一条查「五档处置」→ 含卡 **4,718** vs 无卡 **22** 字符。**泄漏偏向短清单臂**：`active7b-fz` 5 个任务
引用考题定义、**2 个假命中**；`all7b-fz` 2 个、0 假命中 ⇒ **"短清单质量不降反升"就是这么造出来的。**
> **教训（比数字重要）**：泄漏在**路径层面**早已知（答案侧检测已实现），但只做了**答案文本级剔除**，
> 没做**语料级检测**，也没**换干净语料重算** ⇒ **知道了泄漏 ≠ 处理了泄漏**；
> 判别澄清的一半，必须配一次"换干净输入重算"。

**2.10 代码指纹会把"边跑边改"印出来。** `--corpus-root` 冻住语料，**冻不住被执行的代码**；`-fp` 批
四臂顺序跑了约 40 分钟，我中途改仓库 ⇒ 同批裂成两组指纹（625,281 / **629,723** 字符）。
**这是 §2.5 事故的代码侧版本。** 修法：① `--require-same-code` exit 2；② **标题与结论不再写死** ——
「变化的轴」由 `describe_axis()` **从账单逐字段推导**（旧版把「唯一变量是工具清单长度」硬编码进标题，
却用在两臂工具数相同的裁剪对照上 —— **同一段输出里自己印的证据就否掉了自己的标题**）；
**缺字段一律读作「未记录」，不许顶成 0**（否则老账单被判成"裁掉了"，比出假差异）。

**2.11 pytest `--basetemp` 复用 → 143 个假错误级联。** 现象：`419 passed / 143 errors`，全在 setup 的
`assert not self._finalizers`。**根因只有 1 个**：`--basetemp` 指向工作区内 `logs/pytest-tmp`（286 目录），
pytest 启动 `rm_rf(basetemp)` 被**沙箱 safe-delete 守卫**拦下（`SAFE_DELETE_BULK_CONFIRM_REQUIRED count=561`）
⇒ `SystemExit` 落在 fixture setup ⇒ 污染 `tmp_path_factory` finalizer ⇒ **后续级联**。
**⇒ 报错数 ≠ 缺陷数。** 处置：每次用**全新** basetemp（`--basetemp="$(mktemp -d)/…"`）；
验证 `tests/test_agent.py` 换新后 **9 passed**。**⚠ 三次"反向复现"全部无效**（输出带
`Sandbox bypassed (escalation-approved)` ⇒ 守卫根本没加载 ⇒ 那几对**差的是沙箱开关不是 basetemp**）
⇒ **本结论目前只有原始日志作证，无可重复受控复现。**

## 3. 缺陷与诚实边界

**规模**：工具清单已换成真实公开 MCP server —— `[实测]` **47 台/230 工具/82,300 字符**
（指纹 `4a997c197abe961850a58a4fb2cbf871`），`run_context_audit.py --tools-from` 已接通；
**来源必须分开标注**：`page_declared`（别人仓库声明的 schema）vs `introspected`（本机当场 `tools/list`）。
真实数据自带 **13/230（5.7%）完全没有 schema**；`server_info` camel/snake 两方言并存。
**仍差**：47 ≠ 100–200 台、只有 `page_declared` 类、**introspect 模式已实现但从未跑过**；
**任务是自撰的 32 道（没动）**。

> 🔴 **230 个定义把上下文打爆了（机制假设，未验证）**：冒烟 `prompt_tokens` **恰好 4096** 且**工具调用 = 0**。
> 82,300 字符英文 JSON 应约 2 万 token ⇒ 像被窗口截断；旁证是模型自己的话「None of the provided functions
> support … The available functions are related to Twi…」⇒ 它看到**残缺工具集**，判定"没这个功能"并
> **放弃调用** —— 不是"变慢"，是**"停止工作"**。**验证顺序不许颠倒**：① 先等正在跑的批结束
> （**不能中途重启 Ollama**，会把那批变成超时作废）② 提 `num_ctx` 后**同命令重跑**
> ③ ptok 若**仍** 4096 ⇒ **假设必须改写**，不许留着当结论。

**其它**：3605 个工具名里 **296 个（8.2%）有多份互不相同的定义**（`search` 77 种）⇒ 容错策略"任一份
