## 0. 一句话状态（2026-09-18 晚，**以此为准**）

**v4.0 = Agent 上下文与工具预算的自治策展。** 内核是**「准入决策」换域**：
v1 这个数字能不能引用 → v3.0 这条轨迹能不能喂训练 → **v4.0 这段内容该不该进上下文**。

转向依据（**需求侧，不是资产侧**）：重复发送的上下文占 agent 账单约 **62%**；
MCP 工具元数据占上下文窗口 **40-50%**；50 工具选择准确率 **84-95%** → 200 工具
**41-83%** → 740 工具**接近 0**；Gartner 预计 **>40% agentic 项目 2027 年底前被取消**，
首因是成本。受众 = **所有跑 agent 的人**（含只关心钱的老板）。
**验证是确定性数字**（token/成本/成功率）→ 不需要 GPU、不需要训练，
彻底补掉 Q37「模型指标提升给不出」的空洞。

**我承认的两个方法论错误**（都是用户纠正的，值得反复看）：
① 用「复用率 70%」「我的不可替代能力」推荐方向 = **技术轨迹驱动**，
   回答的是「我能做什么」而不是「谁需要什么」；
② 「改别人的 schema」**违反了我自己立的判据**——处置要看「能不能给出可执行动作」，
   而第三方 MCP server 的定义开发者**改不了**，所以那是不可执行的动作。

计划在 `docs/ROADMAP.md` 顶部 **v4.0 节**（R5.0–R5.3 门禁 + 四条不做 + 三条诚实边界）。
**最关键诚实边界**：本机 7B 模型，token 侧结论可迁移（token 数由上下文结构决定），
**成功率侧只在本地口径下成立**。v3.0 降为**领域包 2**；A 股为领域包 1。

### R5.0 已完成（2026-09-20，`docs/r5.0-acceptance.md`，提交 dc5a022/a16da4c）

实验台已落地：`src/findata/contextbudget/`（薄客户端 + 27 工具清单（4 真实实现 /
23 只有定义的沉默工具）+ 仓库语料工具 + GenAI 语义约定遥测 + 记账 agent loop +

1. **工具定义的 token 成本是实测的**（同 payload 切换 `tools` 求差，不靠字符数换算）：
   4 工具 613 / 27 工具 **2277** prompt token；4→27 多花 **1664 token/次**。
   **只有绝对增量可迁移**；「占 92.7%/98%」是短 prompt 的产物，占比必须同时给分母。
2. **模型不匹配的代价是双向的**：同 harness 下 3B 命中 0/6、7B 4/6，而 3B
   **token 反而更高**（30,548 > 28,516）。**换小模型既贵又不准**；
   「路由的收益不是先验正的」。
3. **`reset_for_test()` 曾是「声明与实现不符」**（OTel provider 是进程级单例）：
   测试看起来在验证、其实什么都没验证。**「静默不验证」只能靠身份断言抓。**

**R5.1 的前置条件（不改数据模型就测不了）**：当前 runner 只记 `payload_chars`、
不记返回内容，且返回是散文文本 → **没有"字段"粒度**，「哪些字段被后续引用」
无从回答。R5.1 第一件事是**改数据模型**（结构化返回 + 字段级字符数 + 值指纹），
不是跑分析。

**本机两个新坑**：① 系统代理把 `localhost:11434` 拦成 **502**（httpx 必须
`trust_env=False`，Bash 探活加 `--noproxy '*'`）；② `uv run python` 看到的 `/tmp`
不是 Git Bash 的 `/tmp`（Bash 传路径给 Python 用 Windows 原生绝对路径）。

## 1. v3.0 主线（已降为领域包 2）

一句话命令：`uv run python scripts/run_trust_filter.py`（**默认全量 6 万条**，`--limit 0`）。
丢一批 Agent 轨迹进去，吐出「哪些能喂训练、哪些不能、为什么」，每条判定带证据链。

- 语料**必须真实**：`Salesforce/xlam-function-calling-60k`（ModelScope，ijson 流式）。
  自造样本是循环论证（合成集 100% → held-out 63.6%）
- 核心命题「**形态相同、结论相反**」四个变体：
  ① 停牌（合法缺失）vs 漏采 ② agent 漏填 vs 数据源 schema 缺陷
  ③ "我没认出来"（兜底）vs "数据是坏的" ④ tool schema「值缺失」vs「值放错位置」
  —— 同一个动作做错：**拿一个"我没证据"的判断，去执行一个有代价的动作**
- 当前口径：60000 条 / 100011 次调用 / 命中 1351（2.25%）/ A 样本侧 65 /
  B 工具 schema 侧 1286 / 21 个工具 21 个参数 / **丢弃 0** / 364 例测试
- A 股降为领域包 1；已删 legacy/、findata-agent/、findata/rl/、agentops/synth.py

## 2. 铁律（跨会话最有价值的部分）

### 2.1 三条判据（R2 拷问后固化）

**① 证据强度要分层：「值缺失」与「值放错位置」差一个量级。**
`calculate_electric_field.permitivity` 描述称默认值 8.854e-12、自己没 `default`，
而该值**标在 int 型 `charge`/`distance` 上**（真空介电常数不可能是电荷量的默认值）。
→ 不是"漏标"（可用疏忽解释），是"错位"（疏忽解释不通）。
**分层直接决定处置**：漏了→补上；放错了→移动。统一成"补 default"会让数据源方
两边都标，改得更错。全量错位仅 2 个参数位（`permitivity` 258 次 /
`mean_confidence_interval.confidence` 83 次）。

**② 两种解释都成立时选可逆的动作，别打解释之争。**
`required` 与 description 冲突谁优先？→ **不需要赢**：两种读法下处置都落在
"改 schema"，都不是丢样本。判据 = **丢样本不可逆、改 schema 可逆**。
算术：1 处 schema 缺陷影响 258 条样本，修 1 处消掉 258 条歧义；
丢 258 条什么都解决不了。推论：**处置的风险等级应由证据强度决定，
不该按类别一刀切**（"参数错→丢弃"在多成因上 overshoot，应降为交人工）。

**③ 报数前先问：这个"冲突"是不是数据源的表示层约定。**
类型/默认值冲突探针全量 2162 命中，核出该数据源 **89.1% 的 `default` 本就是
字符串**（`type: int` + `default: "10"`）——是方言不是矛盾。**探针当场删除**。
判据：命中被一两个重复形态主导 → 先抽 3 条读原文。
**一个从不删规则的质检系统，指标只可能虚高。**

### 2.2 处置与措辞

- **处置五档不是四档**（`agentops/triage.py`）：`✓ 正样本 / ⚠️ 需人工 / ✗ 丢弃 /
  ⊘ 不算失败 / 🔧 待修 schema`。第五档意义：**根因在数据源，处置就作用在数据源上**
- 处置选择的判据不只看"有多可疑"，还看 **①能不能给出可执行动作 ②队列长度**。
  5 条 → 人工队列是队列；349 条 → 逐条看等于没有队列，必须结构性修复
- 措辞纪律（写代码写文档都算）：「命中率」≠「发现率」；**命中数 ≠ 错误数**；
  「未命中」≠「干净」（无执行反馈时"正确"观测不到）；变量名也是措辞
  （`n_bad` → `n_hit`）；**口径写进产物本身**（`manifest.note`），别只活在文档里

### 2.3 门禁与可复现

- **文档一致性门禁**（`tests/test_docs_consistency.py`）：① 各文档对测试数只能有
  一个值；② **必须等于 `pytest --collect-only` 真实收集数**。第 ② 条不能省——
  文档可以一起写错（实测 354 这个错数在 6 处共存一个月）。
  **两份拷问文档刻意不在扫描名单里**（要引用历史错数字讲漂移史）
- **可复现三元组**（`manifest.reproducibility`）：`code_commit` + `rules_version`
  （改判定逻辑必须动 `triage.RULES_VERSION`）+ `data` 指纹（sha256 前 16 位 + 字节数）。
  公开数据集会被作者修订，**没有数据指纹就复现不了**

### 2.4 对照实验的元坑（曾差点得出假结论）

**patch 错了函数**：第一版前提敏感度实验 patch 了 `_description_claims_default`，
而判定路径实际走 `default_claim()` + `misplaced_defaults()` → **两臂跑出一模一样的
数字，「结论稳健」差点是假结论**。修法：**加断言先证明 patch 生效**。
→ **对照实验必须先证明"两臂真的不一样"**，否则 0 差值分不清是稳健还是没生效。
前提敏感度结论：**丢弃数不因前提翻转而变（都是 0），但归因会变**
（P1→P2：待修 schema 1286→0，需人工 65→1351）。

## 3. 已知边界与最大缺陷

**最大可扩展性缺陷**：**3605 个工具名里 296 个（8.2%）有多份互不相同的定义**
（`search` 77 种；`time_series` 一个名字对应 4 个不同 API）。容错策略
"任一份 schema 能解释就放行"（不加会误报 45 条）在百万级会**系统性少报**。
缺陷清单的 `(tool, param)` key 在同名多版本下有歧义（本批核过 0/21，
**是运气不是实现保证**）。

**其它**：CI 只跑合成语料 → 真实路径 bug 进不了门禁，改数据层后**必须真跑一次
真实数据**；`corporate_event` 真实路径是空表（有 schema + 消费方，**无采集代码**）。

## 6. 环境提醒（本机）

  用 Glob/Read/Grep 工具替代，或 `git` 这类绝对路径命令

  无法本地复现**，只能靠 CI 验证

  动删除前先 commit
