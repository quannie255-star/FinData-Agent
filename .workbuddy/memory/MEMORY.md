## 0. 方向已定（2026-09-27 用户拍板；权威版 `docs/final-scope.md`）

**收敛到「金融数据可信」，冻结换域与升级规划。** 冻结的是"换域 + 加新能力"，不是停手。

依据三条**可核对事实**（不是怀旧）：① 金融侧是**唯一有运行证据**的；② 唯一有真门禁；
③ `pyproject.description` 本来就是它 ⇒ **收敛成本 = 改 `version` 一个字段**。
**不迁移任何代码**（README/PITCH 09-23 刚改成 v4.0 主线，再改就是第三次横跳）。

**最终目的**：把「这个数字能不能用」从口头判断，变成**一份带证据链、可被第三方核查的产物**。
它不生产数字，只回答"可不可信、为什么" —— 差异化在**归因**不在检测。换域两次是
「这套判断不是只会一件事」的**证据**而非两个产品；**三个域都做成半成品 = 三个都不是产品**，
这才是收敛的理由。

**冻结判据（一句话）**：**一个改动如果不增加"别人能跑起来"的概率，就先不做。**

## 1. v4.0 实验台（**方法学附录**；读数全量在 `docs/r5.0-acceptance.md`）

内核 = 「准入决策」换域（v1 数字能不能引用 → v3.0 轨迹能不能喂训练 → **v4.0 内容该不该进
上下文**）。交付 = `policy.json` + `report.md/json` + `baseline.json`。
**稀缺的不是"裁剪的点子"，是"能证明裁剪没伤结果的闭环"。**

**四条结论，按可辩护度排序**（引用时只许引前三条；第四条是"没测出来"）：

1. **R5.0 = token 侧全项目最强**：32 任务 × 2 臂、唯一变量 = 工具清单长度（27 vs 4）；
   干净语料（210 文件 / `e4deb476c30c93e4`）prompt_tokens **−52.0%**、符号检验
   **p=2.46e-07**、30 正 / 2 负；**但有反例 2/32** ⇒「短清单一定更省」是错的。
   受控探针测得定义 token 差 1,664/次 vs 端到端 1,435.3/次（86%）—— 两条独立路径对上，
   但**不是恒等式**。
2. **⚠ 质量侧已被自己推翻**：原报"不降反升 7→13 / p=0.03125"**作废** —— 那批跑在
   **含答案卡**语料上、用**弱判据**，且泄漏**偏向短清单臂**；干净语料上 `exact_hit` 9 vs 7、
   **k=2 < 6 ⇒ 无分辨力**。
3. **R5.2 唯一跨两个模型复现且显著的质量结论**：**「少给内容」与「不给内容」不是程度差异，
   是两种东西** —— `hint` 在 3B 上 k=6、**6 个不一致对全朝 `fx`、0 朝 hint**（双侧
   p=0.03125），7B 方向一致。且它 **token 侧 p=0.2649 不显著**（hint 让模型多调工具、
   返回总量 +53%）⇒ **"省"不是单调的**。同批另两条：`head` 省 23–25% token 但质量侧只
   "没测到伤害"（**不能说"证明无害"**）；`cap` k=5 **测不出** ⇒ **"两次测不出"≠"两次都没事"**。

**效力边界（缺一条就可能读错）**
1. 7B `-fp` 批**内部分裂**（`fx`/`ch` = `ef9f3bca` vs `ci`/`cp` = `4b313ddb`）
   ⇒ 7B 的 R5.2 **只有 `fx↔ch` 一格能用**。
2. `-fz` 批（214 文件，**含答案卡**）与 `-fx`/`-fp` 批（210，无答案卡）**是两个语料**，
   读数不可混用。
3. **解码仍未固定**（无 seed / 未压 temperature）⇒ 顺序定死：**① 先量噪声下界 →
   ② 再固定解码 → ③ 才写进对照表**，不许颠倒（先固定再量只能量到 0，就不知道现有结论里
   有多少是噪声）。

**噪声下界（已实测）**：7B 两次 token 差 **0.8%** / 逐 token 相同 26/32；3B 差 **0.1%** /
相同 26/32。**噪声在"生成"不在"累积"**（prompt 0.8% vs completion 2.1–7.8%）
⇒ **报 token 必须说清 prompt 侧还是 completion 侧。**

**规模与"没做的"**：工具清单已换真实公开 MCP server（**47 台 / 230 工具 / 82,300 字符**）；
真实数据自带 **13/230（5.7%）完全没有 schema**；**introspect 模式已实现但从未跑过**；
**任务是自撰的 32 道**。

> 🔴 **230 个定义把上下文打爆（机制假设，未验证）**：冒烟 `prompt_tokens` **恰好 4096**
> 且工具调用 = 0；模型自述 "None of the provided functions support…" ⇒ 看到**残缺工具集**
> 后**放弃调用**（不是"变慢"，是**"停止工作"**）。验证顺序不许颠倒：① 等正在跑的批结束
> （**不许中途重启 Ollama**，会把那批变成超时作废）② 提 `num_ctx` 后**同命令重跑**
> ③ 若 ptok **仍** 4096 ⇒ **假设必须改写，不许留着当结论**。

## 2. 铁律（每条都是真事故换来的）

**2.1 三条判据**（①③ 的通用做法已沉淀成 skill `quantitative-claim-audit` 陷阱 5/6/7；
此处只留项目事实）
**① 证据强度要分层：「值缺失」与「值放错位置」差一个量级。**
`calculate_electric_field.permitivity` 描述称默认 8.854e-12、自己没 `default`，而该值
**标在 int 型 `charge`/`distance` 上** ⇒ 不是"漏标"（疏忽可解释），是"错位"（疏忽解释不通）。
**分层直接决定处置：漏了 → 补上；放错了 → 移动。**
**② 两种解释都成立时，选可逆的动作，别打解释之争。** `required` vs description 谁优先？
**不需要赢** —— 两种读法处置都落在"改 schema"。判据 = **丢样本不可逆、改 schema 可逆**
（1 处 schema 缺陷影响 258 条样本，修 1 处消 258 条歧义，丢 258 条什么都不解决）。
**处置风险等级应由证据强度决定，不该按类别一刀切。**
**③ 报数前先问：这个"冲突"是不是数据源的表示层约定。** 类型/默认值冲突探针全量 2162 命中，
核出该源 **89.1% 的 `default` 本就是字符串**（方言不是矛盾）⇒ **探针当场删除**。
**一个从不删规则的质检系统，指标只可能虚高。**

**2.2 处置与措辞。** 五档（`agentops/triage.py`）：`✓ 正样本 / ⚠️ 需人工 / ✗ 丢弃 /
⊘ 不算失败 / 🔧 待修 schema`（第五档 = **根因在数据源，处置就作用在数据源上**）。
选择还看 ①能否给出可执行动作 ②**队列长度**（5 条 → 人工队列是队列；349 条 → 逐条看等于
没有队列，必须结构性修复）。措辞：「命中率」≠「发现率」；**命中数 ≠ 错误数**；
「未命中」≠「干净」（无执行反馈时"正确"观测不到）；变量名也是措辞（`n_bad`→`n_hit`）；
**口径写进产物本身**（`manifest.note`），别只活在文档里。

**2.3 门禁与可复现。** `tests/test_docs_consistency.py`：各文档测试数只能有一个值，且
**必须等于 `pytest --collect-only` 真实收集数**（错数 354 曾在 6 处共存一个月；两份拷问
文档刻意不在扫描名单）。**可复现三元组** = `code_commit` + `rules_version`（改判定逻辑必须动
`triage.RULES_VERSION`）+ `data` 指纹。**代码指纹**：账单 `code_commit` 取自语料根（冻结
快照），**真正执行的代码在工作区** ⇒ 补 `executed_code`；**相对路径是指纹的一部分**。

**2.4 对照实验的元坑（同一个错误犯了三次）。** ① **patch 错函数**（前提敏感度实验 patch 了
`_description_claims_default`，实际走 `default_claim()`+`misplaced_defaults()` ⇒ 两臂一模一样，
"结论稳健"差点是假结论；修法：**加断言先证明 patch 生效**）② **漏 `--model`**（一批"7B"
实跑成 3B，差点把"跨模型差异"读成"噪声很大"）③ **边跑边改仓库**（见 2.5 / 2.10）。
⇒ **"只有一处不同"必须由产物核对，不能由记忆核对**；核对五样：**代码指纹 / 模型 /
语料指纹 / 工具清单 / 裁剪策略**。**臂名是标签不是证据** —— 文件名会撒谎，账单的
`scope.model` 与 `reproducibility.executed_code` 不会。`--require-same-corpus` /
`--require-same-code` 是硬闸门（不一致即 exit 2）。

**2.5 拿本地仓库当语料：冻结 + 指纹化**（通用做法已沉淀成 skill
`corpus-freeze-and-drift-check`）。**事故**：第一臂跑的 22 分钟里提交 4 次 ⇒ 同一臂三次
`list_files` 读到三个目录状态，脚本还在打印「唯一变量是工具清单长度」；事后核出
**4 处漂移 / 570 字符 / 覆盖率 18.7%**。本项目仍要记住的两条：
- **"冻结"由路径保证，不靠自律**（`git worktree` + `--corpus-root`）；**一句声明必须有产物
  能证伪它**，否则不是诚实说明是**口号**。账单指纹看"现在"的磁盘，`check_corpus_drift.py`
  回看"当时"落盘的 trace —— **那次事故只有后者能发现**。
- **盲区要写出来**：说「已核的有 4 处，未核的不知道」，不说「只漂了 4 处」；报漂移要同时报
  **方向**（四处全是 A 更小 ⇒ 结论偏保守，"没威胁结论"≠"可以不说"）。

**2.6 指纹口径：必须测"工具实际读到的东西"。** 字节哈希让主工作区 vs worktree
**误报 53 个文件变了** —— 实为 `core.autocrlf` 把 LF 写成 CRLF，而 `read_text()`
（universal newlines）读到的**逐字相同**；改成"归一化文本哈希 + 规模按**字符数**
（与 `payload_chars` 同口径）"后 **53 → 0** ⇒ 与 2.1③ 同类：**先分清表示层差异，
再谈内容差异。**（Windows 坑：`Path.write_text` 会把 `\n` 翻成 `\r\n`；测试要构造 CRLF
必须用 `write_bytes`。）

**2.7 分辨力下限 = `2^(1-k)`**（k = 配对不一致对数）。**k ≥ 6 才可能有分辨力**
（k<6 时最小 p ≥ 0.0625）⇒「不显著」的正确读法是「**本对照测不出**」，既非"无差异"也非
"等效"；**报"不显著"必须同时报 k**。

**2.8 同一文件的并行编辑会互相覆盖。** 同一条消息里给**同一个文件**发两处 Edit，第二处按
旧内容匹配 ⇒ **一处静默丢失** ⇒ **改同一个文件必须逐个发。**

**2.9 判据泄漏的两个面。** **答案侧**（`grading.has_exam_leak`）：冻结语料曾把 `tasks.py`
（**同时含 32 道题与 `must_contain`**）装进去 ⇒ 模型读它答案里就带上判据（实测 t23 整段讲
`tasks.py` 却引用了 `Task("t23", …)`）。指纹取窄（`must_contain` / `Task\(\s*"t\d\d"` /
`tags=\(\s*"(?:single|multi|cross)"`）—— **一个"泄漏"标记会直接剔数据，误标就是误删**；
泄漏答案 `failed_by="leaked"` 单列并**剔出各档统计**（不重跑：`runs-*.jsonl` 存了原文）。
**语料侧**（`contextbudget/leakcheck.py` + `scripts/check_corpus_leak.py`，exit 3 可进门禁）
三条判据：① **路径**（受保护路径 5 条）② **内容**（与文件名无关 —— **实测抓到判据①漏掉的
2 个文件**：`contextbudget/__init__.py`、`tests/test_contextbudget.py`）⇒ **凡想只靠一份
手写清单下结论的地方，都会低估泄漏面** ③ **重放**（工具确定性 ⇒ 差异不含采样噪声；
`summarize_replay` 单测钉住**变小的查询不能拿来抵账**）。

**泄漏的量化后果**（`[实测]` 已归档 `examples/context-audit/leak-replay-{frozen,noleak}.txt`，
含命令与退出码，09-23 逐字复现；**数字细节读那份归档，不背**）：两个快照差集**正是那 4 个
答案文件**（214 / `00a95aea86927097` vs 210 / `e4deb476c30c93e4`）；16 条真实查询重放
**10/16 在含卡语料上返回更大，共 +45,514 字符**；**泄漏偏向短清单臂** ⇒
**"短清单质量不降反升"就是这么造出来的。**
> **教训（比数字重要）**：泄漏在**路径层面**早已知（答案侧检测已实现），但只做了

## 3. 缺陷与诚实边界

**对外报数三条**：① **token 只占可变运行成本 20–25%**（人工复核 70–75%）⇒ 别把"省 25% token"
说成"省 25% 钱"；② 机制层（找没用过的工具 / 少发定义 / 检索注入 / 成本面板）**已全部商品化**；
③ 结论限定**本机 7B/3B** 口径 —— token 侧可迁移、成功率侧不可。

**面试最该准备的四个"承认"**：① 人工一致性 κ **没做**（只有机器 vs 机器 κ=+0.7417，n=13）；
② 超时归因**只有一个信号**且**刻意不修**；③ held-out 63.6% vs 门禁 ≥0.9 的**红灯不划掉**；
④ **R5.2 质量侧只有 3B 批完整可用**，7B 只剩 `fx↔ch` 一格。

**竞品 Jev 折扣版（完整见 `competitive-landscape.md`）**：关键三条 —— 独立审计实测
**5–25×**（非宣传 20–400×）、**概率校准无公开曲线 = 没法验证**、
`fast-jev-compaction` 把工具结果换成一行提示 ⇒ **看不到返回内容，判的是合理性不是证据**。
⇒ 缝隙只剩两样且必须靠实测站住：**① 证据来自 trace 的引用观测 ② 有配对验证闭环**。
不把闭源付费 API 接进 CI；复刻其协议必须标注「协议仿真，不是 Jev 本体」。

**v3.0 领域包（已降级为领域包 1）**：60000 条 / 100011 次调用 / 命中 1351（2.25%）/
A 侧 65 / B 侧 1286 / 21 工具 21 参数 / **丢弃 0**；核心命题「**形态相同、结论相反**」
= 同一个动作做错：**拿一个"我没证据"的判断，去执行一个有代价的动作。**

**其它已知缺陷**：3605 个工具名里 **296 个（8.2%）有多份互不相同的定义**（`search` 77 种）
⇒ 容错策略"任一份 schema 能解释就放行"在百万级会**系统性少报**。`corporate_event` 曾是空表
（有 schema + 消费方、**无采集代码**）⇒ 全部停牌抑制规则失效，真实告警 7/7 误报；
