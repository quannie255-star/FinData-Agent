# 2026-09-06

## 岗位调研 + 竞品调研 + 架构定调

**做了什么**
- 检索 2026 年在招的 AI Agent / 大模型应用实习 JD（仙工智能、IAV、合肥AI研究院、
  国家超算深圳中心、思必驰、环一科技、萌想科技等），提取技能频次
- 检索 Text2SQL / Data Agent 竞品现状（WrenAI、DB-GPT、Vanna、Dataherald、SuperSonic、
  XiYan）与数据可观测方向（Monte Carlo、Anomalo、Bigeye、Data Workers、Great Expectations）
- 确认行业共识："trust, not syntax, is the engineering problem"（60%+ 业务用户不信 NL2SQL 结果）
- 定位错位竞争点：价值链第三段「数据健康核验」无人与查询链路联动
- 确立主线「查询时数据可信」+ 产品化目标「分析结论的质检网关」
- 论证 A 股域与主线同构（停牌/除权/财报修正/多源口径差异 = 天然数据质量场景）
- 输出六层架构与里程碑（详见 MEMORY.md）

**关键结论**
- 继续做 Text2SQL 是红海；差异化必须落在 post-execution 的可信性，而非 pre-execution 的语义
- 评测（golden set + LLM-as-judge + CI）与可观测（Tracing）是 JD 里少数写、
  但最能拉开差距的能力，必须做进项目
- 拒答率要作为一等公民指标，这是"有业务思考"的最强信号

**未决**
- 等用户确认：主线定位 / 垂直域 / 本轮动工顺序

## M4 Agent 层：LLM 归因器（已完成）

**产出**
- `src/findata/dq/protocol.py`：`Triage` Protocol（`diagnose_all`），
  规则/LLM 两个实现都可注入评测 runner
- `src/findata/agent/llm.py`：`LLMClient` 协议 + `OpenAICompatClient`（requests
  直连 /chat/completions，兼容 DeepSeek/智谱/通义）+ `MockLLMClient`（队列式桩）
- `src/findata/agent/llm_triage.py`：`LLMTriage`、`build_evidence`、`TriageStats`
- `scripts/run_eval.py --triage {baseline,llm,both}`（无 key 时优雅跳过并提示）
- `tests/test_agent.py`（12 个新用例，累计 42）

**核心设计：不信任模型**
1. 白名单校验（根因/级别取受控枚举，`DIAGNOSABLE_CAUSES` 排除 UNKNOWN）
2. 逐条降级：某条非法只降级该条，其余合法结论不连坐
3. 全批兜底：无 key/超时/限流/非 JSON → 退回 `BaselineTriage`，巡检照常出报告
4. `build_evidence` 与规则归因器共用同一批证据，差异只可能来自推理

**关键测试**：模型完全不可用时，评测指标必须与纯规则逐项相等（不得更低）。
这条是"接 LLM 是否该上线"的判据。

**踩坑**
- `MockLLMClient` 初版自己调 BaselineTriage，用 `ProbeContext.__new__` 伪造 ctx，
  很脏 → 重写成队列式桩，只负责返回预置回复
- 统计口径：模型"漏答"应算降级、不算拒收，一度 rejected=13 误报
  → fallback = total - from_llm，rejected 仅统计"给了但非法"
- 信号按批（8 条）发送，测试要用 `default=` 而非 `replies=` 队列，
  否则第二批拿到空回复
- models.py 插入 `DIAGNOSABLE_CAUSES` 时误插进类体，切断 `is_benign` 属性
  → 类定义内插常量后必须立刻 import 验证

**修正了之前的不实承诺**
- 之前承诺"借 Contaminator/注册为算子"——基于"接口对得上"的乐观判断，
  实际看 `curation_eval` 源码后发现：
  - Contaminator 是样本级（sample.id + image/text）
  - findata 故障是表级（symbol + date + column）
  - 硬接需要写"假 Sample"厚适配层，价值被复杂度抵消
  - 改为只借 Cohen's κ（通用指标，接口对得上）
- 修正后 `_interop.py` 顶部明确写了"真借什么 / 不借什么 / 为什么"，
  后续任何人想扩展都从这一段出发

**B1 测试**
- `test_triage_agreement_kappa_via_curation_eval`：检查 source=curation_eval，
  是 B1 真实借用的回归门禁
- `test_triage_agreement_zero_when_llm_returns_nothing`：LLM 不可用时
  κ=1.0——这是"模型让系统不退化"承诺的统计证据

**B2 stage 的关键设计**
